# LLMS p.44–55 — utilization: prompting, ICL, CoT, planning

## 6.1 Prompting (LLMS p.44-49)
- Prompt engineering = manual creation of prompts (LLMS p.44). **Four ingredients**: task description, input data, contextual information and prompt style (p.44-45). Special inputs (KG, tables) are usually **linearized**; code can represent structured data (p.44). Tab. 13 (p.48): examples of QA with documents in triple quotes, meta-review and text-to-SQL.
- Style: clear request; prefixes such as "Let us think step by step" or "You are an expert on this task"; in chat models, decompose long tasks into several turns (p.45).
- **Five design principles** (p.45-46): (1) state the goal clearly (objective, input/output, constraints); (2) decompose into subtasks; (3) provide quality few-shot demonstrations; (4) use a model-friendly format (separators such as ### or triple quotes; instructions in English); (5) role-playing (e.g., "math expert").
- **Tab. 12 — collected tips** (p.47), grouped: task description (T1–T4: be detailed; say what to do, not what to avoid; limit the response length), input (I1–I2: retrieve documents for facts; mark important parts), context (C1–C4: describe intermediate steps; grading criteria with examples; a "ToT in one prompt" with experts), demonstrations (D1–D9: well-formatted examples; retrieve similar ones; diversity; order matters; complexity; have the LLM itself generate zero-shot examples), others (O1–O8: ask the LLM to check the output; tools with descriptions; self-contained prompt without pronouns; order affects comparisons; restrict the output space in multiple choice; use letters for ordering). Paraphrased; the script `prompt_technique_selector.py --tips` lists each tip with its page.
- **Empirical** (Tab. 17, p.68; text p.46) **[DATED: ChatGPT 2023]**: careful prompts improve performance (WikiFact 29.25→31.21; Colored Objects 53.20→66.75; GSM8k with code demonstrations 78.47→79.30); more complex tasks benefit more; with good prompts ChatGPT gets close to supervised baselines in some cases (WikiFact 31.21 vs 34.20), but falls behind in others; recommendation/IR is still far from supervised (p.46).
- **Prompt optimization** (p.46-49): discrete — by gradient (AutoPrompt), by RL (RLPrompt, TEMPERA, PRewrite), by editing (GPS, delete/swap/paraphrase/add operations), by LLM (APE, APO with "textual gradients", GPO with cosine decay of the edit distance, planning with MCTS) (p.46-49); **continuous** — prefix/prompt tuning, context tuning, SPoT (transfer with little data), little explored in the LLM era (p.49).

## 6.2 In-Context Learning (LLMS p.49-52)
- Formulation (Eq. 11, p.49-50): the LLM receives the description I, demonstrations f(x1,y1)…f(xk,yk) and the query f(x_{k+1}, ⎵) and generates ŷ_{k+1}, without gradient updates. Note 35: ICL in GPT-3 = description and/or demonstrations (either one is dispensable) (p.50). **ICL vs instruction tuning**: instruction tuning adjusts the model (fine-tuning) for the task, while ICL only uses prompting; both format tasks in natural language, and instruction tuning improves ICL, especially in zero-shot (LLMS p.50).
- **Demonstration selection** (p.50): heuristics (semantic k-NN, diversity, relevance+diversity) and LLM-based (informativeness, EPR with BM25 + dense retriever, RL, the LLM generates the demos). They should contain enough task information and be relevant to the query.
- **Format** (p.50): template with pairs; task descriptions; CoT; Auto-CoT and least-to-most automate. **Order** (p.50): recency bias; place the most similar ones at the end; entropy metrics; code-length.
- **Mechanism** (p.51-52): pre-training influences (task design, long-range coherence, compositional structure); at inference there are **task recognition** (random labels/inputs in the demos do not hurt much; an irrelevant template still works) and **task learning** (implicit gradient descent via attention; learning simple functions); recognition emerges in small models (350M) and learning only at ≥66B [495]; Meta-ICL; Symbol Tuning with semantics-free labels.

## 6.3 Chain-of-Thought (LLMS p.52-54)
- CoT extends ICL: demonstrations ⟨input, CoT, output⟩ (p.52); "Let's think step by step" generates chains without examples; "Take a deep breath and work on this problem step-by-step" appears as an alternative (p.52). CoT in code is an option (p.52).
- **Better prompts**: diverse and more complex CoTs (p.52). **Improved generation** (p.52-53): sampling (Self-Consistency by majority vote; voting on the k most complex chains; MCR) and verification (DIVERSE with solution/step verifiers; self-verification; reverse reasoning).
- **Structure** (p.53, Fig. 15): tree (ToT; TouT) and graph (GoT; many interactions, inefficient; XoT).
- **When it works** (p.53): emergent ability — only helps sufficiently large models (typically ≥10B); helps step-by-step reasoning tasks and may worsen non-reasoning tasks (MNLI, SST-2, QQP); significant gain only when the standard prompt does poorly. **Why** (p.53-54): code-training hypothesis (no public ablation); IT on non-CoT data does not improve CoT; components symbols/patterns/text, with patterns and text essential, and the correctness of symbols/patterns not critical.

## 6.4 Planning (LLMS p.54-55; Fig. 16)
- Three components: planner (LLM), executor and environment, with memory and feedback (p.54). **Plan generation**: text (Plan-and-Solve, Self-planning, DECOMP, ToolFormer, HuggingGPT) or code (Faithful CoT, PAL, PROGPROMPT, LLM+P/PDDL); code allows verifiable deterministic execution (p.54-55).
- **Feedback**: internal (RAP, ToT, Reflexion) or external (code interpreter, diffusion models, virtual worlds, Generative Agents) (p.55). **Refinement**: reasoning (ReAct, AutoGPT, ChatCoT), backtracking (ToT, DEPS, TIP) and memorization (Reflexion, skill library, vector stores; MemoryBank) (p.55).
- Tab. 11 (p.45) summarizes representatives: ICL (KATE, EPR, SG-ICL, APE...), CoT (Complex CoT, Auto-CoT, Self-consistency, DIVERSE...), planning (Least-to-most, PAL, ReAct, Reflexion, ToT...).
