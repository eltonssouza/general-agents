## Automatic meters
- **[from source]** JVM (`jvm.`), system (`system.`, `process.`, `disk.`), startup (`application.started.time`, `application.ready.time`), logs (`logback.events`/`log4j2.events`), executors, `http.server.requests` (MVC/WebFlux/Jersey; tags `exception`, `method`, `outcome`, `status`, `uri`; `management.metrics.web.server.request.metric-name`; `autotime.enabled=false` + `@Timed`), `http.client.requests` (only injected `RestTemplateBuilder`/`WebClient.Builder`), Tomcat (only with `server.tomcat.mbeanregistry.enabled=true`), `cache.*` (only caches created at startup), GraphQL, DataSource (`jdbc.connections.*`, `hikaricp.*`), Hibernate (`hibernate-micrometer` + `hibernate.generate_statistics=true`), Spring Data repositories, RabbitMQ, Kafka, MongoDB, Jetty, Redis (SBR p.498-512).
- **[from source]** `@Timed`: Boot only supports it directly on `@Controller` classes and `@RequestMapping` methods (Spring MVC and WebFlux) and on Jersey request classes/methods, not on a plain service bean (SBR p.499-501). You can combine `@Timed` on the class and on the method to change the details of a single method (e.g. `extraTags`, `value` with another name) (SBR p.510-511). `longTask = true` turns on a *long task timer* for the method; it requires a separate metric name and can be stacked with the short-task timer (SBR p.512, NOTE). To use `@Timed` where Boot does not support it directly, the book points to the Micrometer documentation (SBR p.512, TIP). `TimedAspect` (the Micrometer aspect for plain beans) is **not** auto-configured nor described in the Reference: the book does not teach that path (anything said about it is [extrapolation]).

## Custom metrics and filters
- **[from source]** Inject `MeterRegistry`; for dependencies between beans use `MeterBinder`; `MeterFilter` beans (always register on the managed registry, **not** on the static methods of `Metrics`) (SBR p.512-515).
- **[from source]** **`MeterFilter` and `renameTag` (SBR p.514-515):** to customize specific meters, declare a `@Bean` of type `MeterFilter`; the book's example renames the tag `mytag.region` to `mytag.area` on all meters whose ID starts with `com.example`, with `MeterFilter.renameTag("com.example", "mytag.region", "mytag.area")` (in `@Configuration(proxyBeanMethods = false)`; Java and Kotlin versions; Java on p.514, Kotlin and the note on p.515). By default all `MeterFilter` beans (and `MeterBinder`s, p.514) are automatically wired to the Spring-managed `MeterRegistry`.

The NOTE on p.515 says to register metrics through the Spring-managed `MeterRegistry` and NOT through the static methods of `Metrics`, because these use the global registry, which is not managed by Spring. The book does not go into more detail than that (for example, it does not say whether filters apply to the global registry): [inference] any conclusion beyond that.
- **[from source]** Common tags: `management.metrics.tags.<k>=v`; per meter: `management.metrics.enable.<prefix>=false` and `management.metrics.distribution.*` (`percentiles-histogram`, `percentiles`, `slo`...) (SBR p.515-516).
- **[from source]** `metrics` endpoint (must be exposed): `/actuator/metrics` and `/actuator/metrics/<name>?tag=K:V`; use the name from the code, not the normalized one; the value is the SUM of the meters matching name and tags (`area:nonheap` sums Code Cache, Compressed Class Space and Metaspace; `&tag=id:Metaspace` filters only Metaspace) (SBR p.517). ## Round 4: `metrics` endpoint in detail and Appendix A.14 descriptions (Actuator)
- **[from source]** `metrics` endpoint (SBR p.517): `/actuator/metrics` lists the meter names and `/actuator/metrics/jvm.memory.max` details one of them; the endpoint is **not available by default** and must be exposed. Use the name from the code (`jvm.memory.max`), not the one normalized by the monitoring system (in Prometheus it appears as `jvm_memory_max`, but the selector remains `jvm.memory.max`). You can append any number of `tag=KEY:VALUE` to the end of the URL to drill down dimensionally, e.g. `/actuator/metrics/jvm.memory.max?tag=area:nonheap`.
- **[from source]** Sum of matching meters (SBR p.517): the reported value is the **sum of the statistics of all meters matching the name and the applied tags**. In the `?tag=area:nonheap` example, the returned `Value` statistic is the sum of the maximum memory sizes of the `Code Cache`, `Compressed Class Space` and `Metaspace` areas. To see only `Metaspace`, add another tag: `/actuator/metrics/jvm.memory.max?tag=area:nonheap&tag=id:Metaspace`. So, with no tag filter the number is the sum of everything; with `area:nonheap` it is the sum of the three non-heap areas; with `area:nonheap&tag=id:Metaspace` it is only Metaspace.
- **[from source]** Where the text describes each family of export properties (body) and where key+default live (Appendix A.14, SBR p.779-794): AppOptics (body p.481; appendix p.779-780), Atlas (body p.482; appendix p.780-781), Datadog (body p.482-483; appendix p.781-782), Dynatrace (body p.483-486; appendix p.782-783), Elastic (body p.486; appendix p.783-784), Ganglia (body p.487; appendix p.785), Graphite (body p.487-488; appendix p.785-786), Humio (body p.489-490; appendix p.786), Influx (body p.490; appendix p.786-788), JMX (body p.490-491; appendix p.788), KairosDB (body p.492; appendix p.788-789), New Relic (body p.492-493; appendix p.789-790), Prometheus (body p.494; appendix p.790-791), SignalFx (body p.494; appendix p.791), Simple (body p.495; appendix p.791), Stackdriver (body p.496; appendix p.792), StatsD (body p.496-497; appendix p.792-793) and Wavefront (body p.497-498; appendix p.793-794).

## Round 4 additions: process monitoring and Cloud Foundry (page details)
- **[from source]** Process monitoring, activation by code: invoke `SpringApplication.addListeners(…)` passing the appropriate `Writer`, which also lets you customize the file name and path in the `Writer` constructor (SBR p.519).
- **[from source]** Cloud Foundry (SBR p.519-520): the `/cloudfoundryapplication` path gives a protected alternative route to all `@Endpoint` beans and lets Cloud Foundry management UIs show full health information instead of just "running"/"stopped"; it is not accessible to regular users and requires a valid UAA token in the request. `management.cloudfoundry.enabled=false` turns the support off; by default the security check makes SSL calls to Cloud Foundry services, so with a UAA/Cloud Controller using a self-signed certificate you need `management.cloudfoundry.skip-ssl-validation=true`. If `server.servlet.context-path` is not `/`, these endpoints come out under the context (e.g. `/app/cloudfoundryapplication/*` with `server.servlet.context-path=/app`); to always have them at `/cloudfoundryapplication/*`, the book shows a Tomcat-specific configuration that overrides `prepareContext` of the `TomcatServletWebServerFactory`, creates a child `StandardContext` at the path `/cloudfoundryapplication` and forwards requests with a servlet (SBR p.519-522).

## Atlas and Datadog: Appendix A.14 keys with defaults and the `lwc-step` rule (round 5)
- **[from source]** Atlas, `management.metrics.export.atlas.*` keys (Appendix A.14, SBR p.780-781): `enabled` (default true); `uri` (`http://localhost:7101/api/v1/publish`); `step` (reporting frequency, default **1m**); `batch-size` (measurements per request; if there are more, several sends; default **10000**, SBR p.780); `connect-timeout` 1s and `read-timeout` 10s; `num-threads` of the publishing scheduler (default 4); `meter-time-to-live` (**default 15m**: a meter with no activity in that period is considered expired and is no longer reported) (SBR p.780-781).
- **[from source]** Atlas, **LWC** part (on-demand streaming): **`lwc-enabled` default false** (streaming off, SBR p.780); `config-uri` (current subscriptions; default `http://localhost:7101/lwc/api/v1/expressions/local-dev`), `eval-uri` (evaluate the data of a subscription; default `http://localhost:7101/lwc/api/v1/evaluate`), `config-refresh-frequency` (refresh the configuration from the LWC service; default 10s) and `config-time-to-live` (lifetime of subscriptions; default 150s) (SBR p.780); `lwc-ignore-publish-step` (default true: in streaming, ignores expressions with the same step as the normal publication, for the case where the data already goes to Atlas) (SBR p.781).
- **[from source]** **`lwc-step`** (default **5s**, SBR p.781): step (frequency) of streaming to Atlas LWC, the highest resolution of the on-demand stream. **Rule from the book:** `lwc-step` must be **less than or equal to** `management.metrics.export.atlas.step`, **and** `step` must be an **even (integer) multiple** of `lwc-step` (SBR p.781).
- **[inference]** Application of the `lwc-step` x `step` rule (own calculation, not in the book): with `step` of 1m (60s), `lwc-step` of 5s, 10s, 12s or 30s comply (60 divided by the value is an integer); **7s violates** (60/7 is not an integer, even though 7s is less than 1m). With `step` of 10s, `lwc-step` of 5s complies and **7s violates** (10/7 is not an integer, even though 7 is less than 10); meeting "less than or equal" is not enough (SBR p.781 for the rule).
- **[from source]** Datadog, `management.metrics.export.datadog.*` keys (Appendix A.14, SBR p.781-782): `api-key` (no default) and `application-key` (no default; not strictly required, but improves the experience by sending descriptions, types and base units of the meters) (SBR p.781); `batch-size` 10000 (several sends if there are more measurements); `connect-timeout` 1s; `read-timeout` 10s; `descriptions` (default true: publish description metadata; turn off to reduce the metadata volume); `enabled` true; `host-tag` (tag mapped to `host`; default `instance`); `step` 1m; `uri` (`https://api.datadoghq.com`, US site; change to another site or to a proxy; the book's example for another site is `management.metrics.export.datadog.uri=https://api.datadoghq.eu`) (SBR p.482-483, 782).
- **[from source]** Where each thing is: Atlas `batch-size` in SBR p.780 and Datadog's in SBR p.782; Atlas `lwc-*` keys and `meter-time-to-live` in SBR p.780-781 (do not use a generic range such as p.780-791).
- **[from source]** AppOptics, `management.metrics.export.appoptics.*` keys (Appendix A.14): `api-token` (API token; **no published default**, empty cell), `batch-size` (default 500; measurements per request, if there are more several requests are made: this rule for AppOptics is on **SBR p.779**, not p.792-793, which is Stackdriver), `connect-timeout` 5s, `enabled` true (SBR p.779); `floor-times` (default false; sends time rounded down, useful when aligning measurements from several hosts), `host-tag` (default `instance`; the tag that is mapped to `@host` when sending to AppOptics), `read-timeout` 10s, `step` 1m, `uri` (default `https://api.appoptics.com/v1/measurements`) (SBR p.780); body: SBR p.481. Check each one with `sbr_lookup.py --prop`.
