Pages = PDF (SBR p.N; printed = N−20). Version 2.7.18 [DATED].

## Spring MVC
- **[from source]** MVC auto-configuration **replaces `@EnableWebMvc`** (do not use them together); it includes `ContentNegotiatingViewResolver`/`BeanNameViewResolver`, static resources and WebJars, converters/formatters, `HttpMessageConverters`, `MessageCodesResolver`, static `index.html` and `ConfigurableWebBindingInitializer` (SBR p.255). To keep and extend: a `@Configuration` of type `WebMvcConfigurer` **without** `@EnableWebMvc`; `WebMvcRegistrations` for your own mapping/adapter; full control with `@EnableWebMvc` (SBR p.255).
- **[from source]** The MVC `ConversionService` is different from the one used for properties: `Duration`/`Period`/`DataSize` and `@DurationUnit` do not apply; date formats in `spring.mvc.format.*` (default `FormatStyle.SHORT`) (SBR p.255-256).
- **[from source]** Static content: `/static`, `/public`, `/resources`, `/META-INF/resources`; `spring.mvc.static-path-pattern` (default `/**`), `spring.web.resources.static-locations`; WebJars at `/webjars/**` (with `webjars-locator-core`, versionless URLs); **do not use `src/main/webapp` with a jar**; cache busting via `spring.web.resources.chain.strategy.content.*` and `fixed.*` (SBR p.257-259).
- **[from source]** **Webjars with JBoss** (note on SBR p.258): with JBoss declare `webjars-locator-jboss-vfs` instead of `webjars-locator-core`; without it, all Webjars resolve to 404 (SBR p.258). On other servers the dependency for versionless URLs is `webjars-locator-core` (SBR p.258).
- **[from source]** Path matching: the **suffix (`.json`) comes disabled and deprecated**; use `spring.mvc.contentnegotiation.favor-parameter`; re-enabling requires `favor-path-extension` + `pathmatch.use-suffix-pattern`; the default is `PathPatternParser` (`spring.mvc.pathmatch.matching-strategy=ant-path-matcher` for the old one) and it is incompatible with suffix and with `spring.mvc.servlet.path` (SBR p.260-262). `spring.mvc.throw-exception-if-no-handler-found=true` requires limiting `static-path-pattern` or `spring.web.resources.add-mappings=false` (SBR p.262).
- **[from source]** Auto-configured templates: FreeMarker, Groovy, Thymeleaf, Mustache in `src/main/resources/templates`; **avoid JSP** (SBR p.262-263, 282).
- **[from source]** Errors: global `/error` (JSON for machines, HTML "whitelabel" for browsers); customize with `ErrorController`, `ErrorAttributes`, `@ControllerAdvice`, `404.html` or `5xx.ftlh` pages in the `/error` directory, `ErrorViewResolver`, `ErrorPageRegistrar` (SBR p.263-269). **`ErrorPageRegistrar`** (for apps without Spring MVC; works directly with the embedded servlet container, even without a `DispatcherServlet`): a `@Bean` of type `ErrorPageRegistrar` that calls `registry.addErrorPages(new ErrorPage(HttpStatus.BAD_REQUEST, "/400"))` (SBR p.269, Java example; Kotlin on p.270). If the `ErrorPage` points to a path handled by a `Filter` (common in Jersey and Wicket), the filter must be registered explicitly for the `ERROR` dispatcher: `@Bean FilterRegistrationBean<MyFilter>` with `registration.setDispatcherTypes(EnumSet.allOf(DispatcherType.class))`, because the default `FilterRegistrationBean` **does not include** the `ERROR` type (SBR p.271; the note introducing the case is on p.270). Filters need the `ERROR` dispatcher explicitly; in a war there is an error page filter; with Spring Security use `spring.security.filter.dispatcher-types` (SBR p.270-272). `server.error.whitelabel.enabled=false` (SBR p.639).
- **[from source]** CORS: `@CrossOrigin` or `addCorsMappings` in a `WebMvcConfigurer` (SBR p.272).

## Jersey and containers
- **[from source]** Jersey: own starter, `ResourceConfig` bean, register endpoints with `register(...)` (not `packages()` in an executable jar); `spring.jersey.type=filter` for coexistence with another framework + `FILTER_FORWARD_ON_404`; with method-level Spring Security, `jersey.config.server.response.setStatusOverSendError=true` (SBR p.273-275, 594-595).
- **[from source]** The embedded container listens on **8080** by default (SBR p.275). Servlet/Filter/Listener as `@Bean` (a single servlet maps `/`; filters `/*`; order via `@Order` on the **class**, not on the `@Bean` method); `ServletContextInitializer`; `@ServletComponentScan` (SBR p.275-276, 557-558).
- **[from source]** Common properties: `server.port`, `server.address`, `server.servlet.session.*` (includes `cookie.same-site`), `server.error.path`, SSL, compression, `server.servlet.encoding.*`; specific ones in `server.tomcat.*` and `server.undertow.*`; `WebServerFactoryCustomizer` for the rest (SBR p.277-281).
- **[from source, how-to]** Switching servers: exclude `spring-boot-starter-tomcat` and include `-jetty`/`-undertow`; Jetty 9.4 does not support Servlet 4.0 (that is why the book's example overrides `servlet-api.version` to 3.1.0); to use Jetty 10 (Servlet 4.0) set `jetty.version` to 10.0.8, exclude the Tomcat starter and exclude from `spring-boot-starter-jetty` the Jetty 9-specific dependencies (`websocket-server` and `javax-websocket-server-impl`) (SBR p.569-570). In WebFlux, swapping Reactor Netty for Undertow in Gradle uses `modules { module(...) { replacedBy(...) } }` on `spring-boot-starter-reactor-netty` (SBR p.570). The Reference does not state Jetty 10's minimum Java (see datado.md). `server.port=-1` turns off HTTP while keeping the context; `0` = random port; discover the port via `WebServerInitializedEvent` (SBR p.571). Compression: `server.compression.enabled`, `min-response-size` (2048 bytes), `mime-types` (SBR p.572-573). SSL: `server.ssl.key-store*` or PEM (`certificate`, `certificate-private-key`, `trust-certificate`); **HTTP and HTTPS together require programmatic config** (SBR p.573-574). HTTP/2: `server.http2.enabled` (h2 requires SSL; otherwise h2c); per-server details in the "HTTP/2, TLS and PEM" section below (SBR p.574-575).
- **[from source, how-to]** Behind a proxy: `server.forward-headers-strategy` = `NATIVE`/`FRAMEWORK`/`NONE` (default `NATIVE` on Cloud Foundry/Heroku/Kubernetes, `NONE` otherwise); `server.tomcat.remoteip.*`; an empty `internal-proxies` trusts everyone (not in production) (SBR p.580-582). Details and the NATIVE vs FRAMEWORK difference in the "Behind a proxy: step by step" section below. Access log: `server.tomcat.accesslog.*`, `server.undertow.accesslog.*`, `server.jetty.accesslog.*` (SBR p.579-580). `@ServerEndpoint` requires `ServerEndpointExporter` (SBR p.586).
- **[from source, how-to]** Multipart: default 1 MB per file and 10 MB per request; `spring.servlet.multipart.max-file-size=-1` = unlimited (SBR p.591). **WebFlux:** the WebFlux prefix has no maximum file size key like the Servlet one; the keys are `spring.webflux.multipart.file-storage-directory` (parts above `max-in-memory-size` go to disk, default `spring-multipart` folder in the temp directory), `max-in-memory-size` (256KB; -1 = all in memory), `max-parts` (-1 = no limit), `max-disk-usage-per-part` (-1B), `max-headers-size` (10KB), `headers-charset` (UTF-8) and `streaming` (false); `file-storage-directory`, `max-in-memory-size` and `max-disk-usage-per-part` are ignored with `streaming=true` (SBR p.747). JSP: war only (Tomcat/Jetty), Undertow does not support it (SBR p.282).

## WebFlux
- **[from source]** With `starter-web` **and** `starter-webflux`, Boot configures **MVC** (so the `WebClient` can be used in MVC apps); force reactive with `SpringApplication.setWebApplicationType` and `WebApplicationType.REACTIVE` (SBR p.289). Auto-config of codecs and static resources; `WebFluxConfigurer` without `@EnableWebFlux`; `spring.webflux.*`; `spring.codec.*`; WebFlux **does not** become a war (SBR p.289-292).
- **[from source]** Reactive errors: `WebExceptionHandler`, `ErrorWebExceptionHandler`/`AbstractErrorWebExceptionHandler`; default error view `error/error` (different from MVC) (SBR p.292-296). Boot's web filter order: MetricsWebFilter, WebFilterChainProxy, HttpTraceWebFilter (SBR p.297).
- **[from source]** Supported reactive servers: Reactor Netty, Tomcat, Jetty and Undertow, default port 8080 (SBR p.297); `ReactorResourceFactory`/`JettyResourceFactory` shared with the `WebClient` (SBR p.298-300). **Reactor Netty is the reactive default**: `spring-boot-starter-webflux` depends on it via `spring-boot-starter-reactor-netty` (swap for `spring-boot-starter-tomcat`, `-jetty` or `-undertow`), and war is not supported because the application runs on embedded Reactor Netty by default (SBR p.428, 569, 575, 659). (Round 2 correction: pages 297-300 only list the servers; the "default" is on p.428, 569, 575 and 659.)
- **[from source]** WebFlux in detail: annotated and functional styles (`RouterFunction` in beans; orderable) (SBR p.283-289); date formats from `spring.webflux.format.*` (default `FormatStyle.SHORT`) and the `addFormatters` method of a `WebFluxConfigurer` (SBR p.289); codecs: `CodecConfigurer`, `spring.codec.*`, `CodecCustomizer` (and `spring.jackson.*` on the Jackson codec) (SBR p.290); static resources in `/static`, `/public`, `/resources`, `/META-INF/resources` with `spring.webflux.static-path-pattern`, `spring.web.resources.static-locations` (replaces the defaults and changes welcome page detection), `/webjars/**`; welcome page: static `index.html`, otherwise the `index` template (SBR p.291-292); FreeMarker, Thymeleaf and Mustache templates in `src/main/resources/templates` (SBR p.292); error: Boot's `WebExceptionHandler`, `ErrorAttributes`, `ErrorWebExceptionHandler`/`AbstractErrorWebExceptionHandler`, a subclass of `DefaultErrorWebExceptionHandler`, exceptions handled in a controller only enter the metrics if set as a request attribute (SBR p.292-295); error pages by code or mask (`4xx`, `5xx`) in `error/*`, default view `error/error` (MVC: `error`) (SBR p.296-297); `WebFilter` beans are picked up on their own; Boot's orders: `MetricsWebFilter` HIGHEST_PRECEDENCE + 1, `WebFilterChainProxy` -100, `HttpTraceWebFilter` LOWEST_PRECEDENCE - 10 (SBR p.297). The book's table gives only the order values; that "lower value runs first" (hence `MetricsWebFilter` before `WebFilterChainProxy` and that before `HttpTraceWebFilter`) is an **[inference]** from the semantics of `Ordered`/`@Order`, it is not written on p.297 (the book only says that filters whose order matters implement `Ordered` or use `@Order`). Literal error page examples: static 404 in public/error/404.html (any static location works) and 5xx with a Mustache template in templates/error/5xx.mustache (SBR p.296-297). Reactive server customization: common `server.*`, `server.netty.*`, `WebServerFactoryCustomizer<ConfigurableReactiveWebServerFactory>` and `NettyReactiveWebServerFactory` with `addServerCustomizers` (e.g. `idleTimeout`); auto-configured customizers still apply to a factory of your own (SBR p.297-300).

## Graceful shutdown
- **[from source]** Supported on all four servers, servlet and reactive; `server.shutdown=graceful` and `spring.lifecycle.timeout-per-shutdown-phase` (e.g. `20s`); Jetty/Netty/Tomcat stop accepting on the network, **Undertow responds 503**; Tomcat 9.0.33+; the IDE may not send SIGTERM (SBR p.300-301). Default in Appendix A: `server.shutdown=immediate` and timeout 30s (SBR p.759, 672).
- **[from source]** On Kubernetes combine with `preStop` and `terminationGracePeriodSeconds` (SBR p.527-528).

## HTTP/2, TLS and PEM (round 4)
- **[from source]** Declarative SSL via `server.ssl.*`: the book's example uses `server.port=8443` with `server.ssl.key-store` (`classpath:keystore.jks`), `server.ssl.key-store-password` and `server.ssl.key-password`; with that, the plain HTTP connector on 8080 no longer exists. Boot does not support HTTP and HTTPS at the same time through `application.properties` alone: one of the two must be configured in code, and the book recommends leaving HTTPS in the properties because the HTTP connector is the easiest to set up programmatically (SBR p.573-574).
- **[from source]** PEM key: prefer PKCS#8, whose file starts with `-----BEGIN PRIVATE KEY-----` or `-----BEGIN ENCRYPTED PRIVATE KEY-----`. PKCS#1 files (header `-----BEGIN RSA PRIVATE KEY-----`) or SEC 1 (`-----BEGIN EC PRIVATE KEY-----`) must be converted with `openssl pkcs8 -topk8 -nocrypt -in <input file> -out <output file>` (SBR p.574). The three PEM properties in the example are `server.ssl.certificate`, `server.ssl.certificate-private-key` and `server.ssl.trust-certificate`, all pointing to `classpath:` (SBR p.574).
- **[from source]** `server.http2.enabled` turns on HTTP/2: **h2** = HTTP/2 over TLS, **h2c** = HTTP/2 over plain TCP. With SSL on, h2 is used; without SSL, h2c (useful when a proxy terminates TLS). Support depends on the server and the JDK, because not every JDK 8 ships the ALPN protocol (SBR p.574).
- **[from source]** **Tomcat 9.0.x:** native h2c; native h2 only on JDK 9+. On JDK 8, h2 requires the `libtcnative` library (and dependencies) installed on the OS and its directory on the JVM library path, for example `-Djava.library.path=/usr/local/opt/tomcat-native/lib`. Without it, Tomcat 9 on JDK 8 with HTTP/2 and SSL logs an ERROR saying the upgrade handler `Http2Protocol` only supports upgrade via ALPN; the error is **not fatal** and the application starts with HTTP/1.1 + SSL (SBR p.574-575).
- **[from source]** **Jetty:** requires the dependency `org.eclipse.jetty.http2:http2-server`; h2c needs nothing more; h2 requires **one** of these, depending on the deployment: `org.eclipse.jetty:jetty-alpn-java-server` (JDK 9+), `org.eclipse.jetty:jetty-alpn-openjdk8-server` (JDK 8u252+) or `org.eclipse.jetty:jetty-alpn-conscrypt-server` plus the Conscrypt library (no JDK requirement) (SBR p.575).
- **[from source]** **Reactor Netty** (the WebFlux starter's default server): h2c on JDK 8+ with no extra dependencies; h2 using JDK 9+ support; on JDK 8 or for optimal performance there is h2 with native libraries, via the dependency `io.netty:netty-tcnative-boringssl-static` (uber jar with natives for all platforms, version managed by Boot; you can import just one classifier). **Undertow** 1.4.0+: h2 and h2c on JDK 8 with no additional dependencies (SBR p.575).
- **[from source]** Other options from the same how-to: Tomcat accepts **several connectors** (HTTP and HTTPS) by adding a `Connector` (`org.apache.coyote.http11.Http11NioProtocol`, port 8081 in the example) through `addAdditionalTomcatConnectors` in a `WebServerFactoryCustomizer<TomcatServletWebServerFactory>` (SBR p.582). For Undertow with a second listener use `UndertowBuilderCustomizer` via `addBuilderCustomizers` and `addHttpListener` (SBR p.585).

## Behind a proxy: step by step (round 4)
- **[from source]** The problem: behind a proxy/load balancer/cloud, the request's host, port and scheme change along the way (the app runs on `10.10.10.10:8080`, but clients should see `example.org`). RFC 7239 defines the `Forwarded` header; there are also the non-standard `X-Forwarded-Host`, `X-Forwarded-Port`, `X-Forwarded-Proto`, `X-Forwarded-Ssl` and `X-Forwarded-Prefix`; Boot can read them and use them when building links in 302, JSON or HTML responses (SBR p.580).
- **[from source]** Choosing `server.forward-headers-strategy`: **NATIVE** is enough if the proxy sends the common `X-Forwarded-For` and `X-Forwarded-Proto` (the web server itself handles it); if that is not enough, **FRAMEWORK** uses Spring Framework's `ForwardedHeaderFilter` (servlet) or `ForwardedHeaderTransformer` (reactive); **NONE** turns off automatic handling. The default is NATIVE on Cloud Foundry, Heroku and Kubernetes and NONE otherwise (SBR p.580-581).
- **[from source]** Important TIP: with Tomcat and SSL terminated at the proxy, set `server.tomcat.redirect-context-root=false`, so that `X-Forwarded-Proto` is honored **before** any redirect (this is the remedy for redirects that come back with the wrong scheme or port) (SBR p.581).
- **[from source]** Tomcat: the header names are configurable (`server.tomcat.remoteip.remote-ip-header` and `server.tomcat.remoteip.protocol-header`); the regex of trusted internal proxies (`server.tomcat.remoteip.internal-proxies`, default in Appendix A) can be replaced, and leaving it empty trusts all proxies (do not do this in production) (SBR p.581-582). **Either** of the two `remoteip.*` properties (`remote-ip-header` or `protocol-header`) turns on the `RemoteIpValve`; the alternative is to add the valve through a `WebServerFactoryCustomizer` on the `TomcatServletWebServerFactory` (SBR p.643). For full control, turn off the automatic one (`server.forward-headers-strategy=NONE`) and add your own valve instance in a `WebServerFactoryCustomizer` (SBR p.582). To require HTTPS in Spring Security use a `SecurityFilterChain` bean with `requiresChannel` and `requiresSecure` (SBR p.643-644).

## Embedded server: customization, servlet/filter registration and cookies (round 4)
- **[from source]** Before writing code, look for a key in the `server.*` namespace (`server.tomcat.*`, `server.jetty.*` etc.); only if none exists use `WebServerFactoryCustomizer`, choosing the variant for the server and stack (servlet or reactive) (SBR p.576). Auto-configured customizers have order 0 and run **before** yours, unless yours declares an explicit order. Factories: `TomcatServletWebServerFactory`/`TomcatReactiveWebServerFactory`, `JettyServletWebServerFactory`/`JettyReactiveWebServerFactory`, `UndertowServletWebServerFactory`/`UndertowReactiveWebServerFactory` and, reactive only, `NettyReactiveWebServerFactory`. Declaring your own `WebServerFactory` bean replaces Boot's, but the auto-configured customizers are still applied to it (SBR p.577, 282).
- **[from source]** Servlet/Filter/Listener as beans enter the container **very early**: do not make them depend on `DataSource`/JPA; if needed, initialize the beans lazily. For mappings and init params use `FilterRegistrationBean`/`ServletRegistrationBean`; without `dispatcherType` the filter uses `REQUEST` (the specification's default). To **turn off** the automatic registration of a `Filter` or `Servlet`, create its registration bean and call `setEnabled(false)` (SBR p.577-578). `@ServletComponentScan` scans from the package of the annotated class and has no effect in a standalone container (SBR p.578-579, 276).
- **[from source]** Default mapping: a single `Servlet` maps `/`; several use the bean name as the path prefix; filters map `/*`. Filter order: normally leave it unordered; use `@Order` or `Ordered` on the filter class (not on the method that creates the bean), or `setOrder` on the `FilterRegistrationBean` when you cannot change the class; avoid a filter that reads the body at `Ordered.HIGHEST_PRECEDENCE` (it may conflict with the encoding configuration); a filter that wraps the request must have an order lower than or equal to `OrderedFilter.REQUEST_WRAPPER_FILTER_MAX_ORDER`. To see the order of all filters turn on `logging.level.web=debug`. For a filter that interacts with other beans consider `DelegatingFilterProxyRegistrationBean` (SBR p.276).
- **[from source]** Embedded containers **do not run** `ServletContainerInitializer` or `WebApplicationInitializer` (a deliberate decision, so as not to break libraries designed for war); use a `ServletContextInitializer` bean (method `onStartup`) (SBR p.276). The `ServletContext` is only set during server startup, so beans do not reliably receive it at initialization: inject the `ApplicationContext` and access it on demand, or use an `ApplicationListener<ApplicationStartedEvent>` (SBR p.277).
- **[from source]** Session and cookies: `server.servlet.session.persistent`, `server.servlet.session.timeout`, `server.servlet.session.store-dir` and `server.servlet.session.cookie.*`. `server.servlet.session.cookie.same-site` (e.g. `none`) applies to auto-configured Tomcat, Jetty and Undertow and also to Spring Session servlet's `SessionRepository`; for other `HttpServletResponse` cookies use a `CookieSameSiteSupplier` bean (e.g. `CookieSameSiteSupplier.ofLax().whenHasNameMatching("myapp.*")`) (SBR p.278-279). Encoding: `server.servlet.encoding.*`; the `Accept-Language` locale-to-charset mapping has per-container defaults and can be changed with `server.servlet.encoding.mapping` (e.g. `server.servlet.encoding.mapping.ko=UTF-8`) (SBR p.279).
- **[from source]** "Version 0" cookies: embedded Tomcat does not support them by default and may throw `IllegalArgumentException: An invalid character [32] was present in the Cookie value`; ideally write values compatible with newer specifications; if that is not possible, use a `WebServerFactoryCustomizer` that adds a `TomcatContextCustomizer` with `LegacyCookieProcessor` (SBR p.583-584). Tomcat's MBean registry comes **off** (less memory); turn it on with `server.tomcat.mbeanregistry.enabled=true` for Micrometer to expose Tomcat metrics (SBR p.585).
- **[from source]** Access log: Tomcat uses `server.tomcat.accesslog.enabled` and `server.tomcat.accesslog.pattern` (e.g. `%t %a %r %s (%D ms)`); the `logs` directory is under Tomcat's base directory, which by default is **temporary**: set `server.tomcat.basedir` or use an absolute path (SBR p.579). Undertow: `server.undertow.accesslog.enabled` and `server.undertow.accesslog.pattern`; to use `%D` (response time) you need `server.undertow.options.server.record-request-start-time=true`; logs go in `logs` relative to the working directory, changeable via `server.undertow.accesslog.dir` (SBR p.579-580). Jetty: `server.jetty.accesslog.enabled` and `server.jetty.accesslog.filename`; by default the logs go to `System.err` (SBR p.580).
- **[from source]** JSP (reinforcement): with Jetty and Tomcat it only works with war packaging (an executable war runs with `java -jar` and also deploys to a standard container); an executable jar does not support JSP; Undertow does not support JSP; your own `error.jsp` page does not replace the default error view (use ordinary error pages) (SBR p.282). In a war, the error page filter can only forward if the response has not yet been committed; WebSphere 8.0+ commits the response at the end of `service`, so set `com.ibm.ws.webcontainer.invokeFlushAfterService` to false; to access the principal on an error page with Spring Security, `spring.security.filter.dispatcher-types` must contain async, error, forward, request (SBR p.272).
- **[from source]** Jersey (details): the servlet is registered by default at `/*` (change with `@ApplicationPath` on the `ResourceConfig`) by the `jerseyServletRegistration` bean, initialized lazily (`spring.jersey.servlet.load-on-startup`); as a filter (`spring.jersey.type=filter`) the bean is `jerseyFilterRegistration`, with order in `spring.jersey.filter.order`; as a filter there must be a servlet for whatever Jersey does not handle (perhaps `server.servlet.register-default-servlet=true`); `spring.jersey.init.*` passes init params; `ResourceConfigCustomizer` for advanced tweaks; endpoints must be `@Component` with HTTP annotations (`@GET`, `@Path`); Apache CXF requires registering its Servlet or Filter as a `@Bean` (SBR p.273-275).

## MVC and HTTP clients: how-to details (round 4)
- **[from source]** JSON/XML: any `@RestController` returns JSON if Jackson 2 is on the classpath (SBR p.587); for XML add `jackson-dataformat-xml` or, without it, with JAXB available, annotate the type with `@XmlRootElement`; JAXB only comes out of the box on Java 8 (on newer Java add `jaxb-runtime`); to see XML you may need to send `Accept: text/xml` (SBR p.588-589).
- **[from source]** `ObjectMapper`/`XmlMapper` created by Boot: `MapperFeature.DEFAULT_VIEW_INCLUSION`, `DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES`, `SerializationFeature.WRITE_DATES_AS_TIMESTAMPS` and `SerializationFeature.WRITE_DURATIONS_AS_TIMESTAMPS` come **disabled** (SBR p.589-590). Jackson features map to `spring.jackson.deserialization.<name>`, `spring.jackson.generator.<name>`, `spring.jackson.mapper.<name>`, `spring.jackson.parser.<name>`, `spring.jackson.serialization.<name>` (true/false) and `spring.jackson.default-property-inclusion` (always, non_null, non_absent, non_default, non_empty); example: `spring.jackson.serialization.indent_output=true` (relaxed binding: the case does not need to match `INDENT_OUTPUT`). This applies to the auto-configured `Jackson2ObjectMapperBuilder`; `Jackson2ObjectMapperBuilderCustomizer` beans are orderable (Boot's has order 0) and beans of type `Module` are registered automatically (SBR p.590). Replacing the `ObjectMapper` entirely (a `@Primary` `@Bean`, or a `Jackson2ObjectMapperBuilder`) turns off all of its auto-configuration; `MappingJackson2HttpMessageConverter` beans replace the default and there is the utility bean `HttpMessageConverters` (SBR p.590-591).
- **[from source]** `@ResponseBody`: additional converters come in as beans (one of the same type as a default replaces it) or via `configureMessageConverters` of a `WebMvcConfigurer`, where you only need to supply the additional ones; with `@EnableWebMvc` you take over everything, via `getMessageConverters` of `WebMvcConfigurationSupport` (SBR p.591). Multipart: Boot uses the Servlet 3 `Part` API; default limits of 1 MB per file and 10 MB per request, adjustable (including the temp directory and the threshold for writing to disk) through the `MultipartProperties` properties; `spring.servlet.multipart.max-file-size=-1` = unlimited (SBR p.591); the book recommends the container's own support instead of Apache Commons FileUpload (SBR p.592).
- **[from source]** DispatcherServlet: everything is served at `/`; for another path use `spring.mvc.servlet.path=/mypath`; extra servlets come in as a `Servlet` `@Bean` or `ServletRegistrationBean`; when configuring the `DispatcherServlet` yourself, also provide a `DispatcherServletPath` bean. For full MVC control provide your `@Configuration` with `@EnableWebMvc` (SBR p.592).
- **[from source]** ViewResolvers installed by `WebMvcAutoConfiguration`: `InternalResourceViewResolver` (`defaultViewResolver`; locates physical resources that can be rendered by the `DefaultServlet`, including static ones and JSP pages; applies a prefix and suffix to the view name and looks for the resource in the servlet context; empty prefix and suffix, adjustable in `spring.mvc.view.prefix` and `spring.mvc.view.suffix`); `BeanNameViewResolver` (`beanNameViewResolver`); `ContentNegotiatingViewResolver` (`viewResolver`) only if there are beans of type `View` (turn it off by defining a bean named `viewResolver`); Thymeleaf: `spring.thymeleaf.prefix` `classpath:/templates/` and `spring.thymeleaf.suffix` `.html`; FreeMarker: `spring.freemarker.templateLoaderPath` `classpath:/templates/`, empty prefix and suffix `.ftlh`; Groovy: prefix `classpath:/templates/` and suffix `.tpl`; Mustache: prefix `classpath:/templates/` and suffix `.mustache`. Each can be replaced by a bean of the same name (`thymeleafViewResolver`, `freeMarkerViewResolver`, `groovyMarkupViewResolver`, `mustacheViewResolver`) (SBR p.592-593).
- **[from source]** Jersey with method-level Spring Security: `jersey.config.server.response.setStatusOverSendError=true` on the `ResourceConfig`, so Jersey uses `setStatus(int)` rather than `sendError(int)`, avoiding committing the response before Security reports the failure (SBR p.594). RestTemplate with a proxy: use a `RestTemplateCustomizer` with the `RestTemplateBuilder`; the details depend on the request factory used (SBR p.596). WebClient with Reactor Netty: provide a `ClientHttpConnector` bean (example: 60 s connection timeout and `ReadTimeoutHandler`), using the `ReactorResourceFactory` to share the connection provider and event loops with the server (SBR p.596-598).

- **[from source]** Proxy and HTTP/2 (body p.574-575, 580-582): `server.forward-headers-strategy` handles the `X-Forwarded-*` headers and `server.http2.enabled` defaults to false (SBR p.755); `server.tomcat.redirect-context-root` defaults to true and the appendix description says to set it to false when SSL is terminated at the proxy; `server.tomcat.remoteip.host-header` default `X-Forwarded-Host`, `port-header` default `X-Forwarded-Port`, `protocol-header-https-value` default `https` (SBR p.763-764).

## Static resources, error and port: small page details (round 4)
- **[from source]** Cache busting of static resources: links are rewritten in templates at runtime by a `ResourceUrlEncodingFilter`, auto-configured for Thymeleaf and FreeMarker; with JSP you must declare it manually; other template engines only with their own macros/helpers and the `ResourceUrlProvider` (SBR p.259). Dynamic JavaScript module loaders do not tolerate renaming files; so the "fixed" strategy adds a static version to the URL without changing the file name and can be combined with the "content" strategy: with `spring.web.resources.chain.strategy.fixed.paths=/js/lib/` and `fixed.version=v12`, modules under `/js/lib/` come out as `/v12/js/lib/mymodule.js` and the other resources use the content strategy (SBR p.259).
- **[from source]** MVC error: `BasicErrorController` can be the base of your own `ErrorController`, useful for handling a new content type (the default handles `text/html` specifically and falls back for the rest): extend it, add a public method with `@RequestMapping` and a `produces` attribute and create a bean of the new type; a `@ControllerAdvice` customizes the JSON for a controller and/or exception (SBR p.263). Turning off the whitelabel page with `server.error.whitelabel.enabled=false` restores the servlet container's default, but Boot still tries to resolve the error view, so the best is to provide your own page: an `error.html` template (Thymeleaf) or `error.ftlh` (FreeMarker), a `View` resolved with the name `error`, a `@Controller` for the `/error` path or, if there is a `BeanNameViewResolver`, a `@Bean` named `error` (SBR p.639).
- **[from source]** Port in tests: `@LocalServerPort` is a meta-annotation of `@Value("${local.server.port}")`; do not try to inject the port in an ordinary application, because the value only exists after the container is initialized and the application code callbacks are processed before that (SBR p.572). Discovering the random port at runtime: `WebServerInitializedEvent` (SBR p.571-572). HTTP compression is supported by Jetty, Tomcat, Reactor Netty and Undertow (SBR p.572).
- **[from source]** JWT resource server without a JWK Set URI: point `spring.security.oauth2.resourceserver.jwt.public-key-location` to a file with the public key in x509 PEM format; `spring.security.oauth2.resourceserver.jwt.audiences` defines the expected values of the `aud` claim (e.g. `audiences[0]=my-audience`); the same properties apply to servlet and reactive; alternatively, define your own `JwtDecoder` bean (servlet) or `ReactiveJwtDecoder` (reactive) (SBR p.310). For opaque tokens, the `opaquetoken.{introspection-uri, client-id, client-secret}` properties validate by introspection (SBR p.310) and, alternatively, you define an `OpaqueTokenIntrospector` bean (servlet) or `ReactiveOpaqueTokenIntrospector` (reactive) (SBR p.311).

## Small MVC and client details (round 4, part 2)
- **[from source]** `MessageCodesResolver`: setting `spring.mvc.message-codes-resolver-format` to `PREFIX_ERROR_CODE` or `POSTFIX_ERROR_CODE` makes Boot create one (see the `DefaultMessageCodesResolver.Format` enum); static content uses MVC's `ResourceHttpRequestHandler` (customizable with `addResourceHandlers` of a `WebMvcConfigurer`); the container's default servlet is disabled in a standalone application and is turned on with `server.servlet.register-default-servlet`; it is only a fallback for whatever the `DispatcherServlet` does not handle (SBR p.257).
- **[from source]** Error via `@ControllerAdvice` (SBR p.264-265): the example extends `ResponseEntityExceptionHandler`, restricts by `basePackageClasses` and returns an error-body POJO with the status obtained from `RequestDispatcher.ERROR_STATUS_CODE`; for controllers in that package the POJO's JSON replaces the `ErrorAttributes` representation. Exceptions handled at the controller level may not be recorded by the metrics infrastructure: register them as a request attribute (SBR p.265).
- **[from source]** `RestTemplate` with a proxy (SBR p.423-426): `RestTemplateCustomizer` beans are applied to every template created by the auto-configured `RestTemplateBuilder`; the example configures a proxy for all hosts except `192.168.0.5` with `HttpClient` (Apache), `DefaultProxyRoutePlanner` and `HttpComponentsClientHttpRequestFactory`. To replace the whole builder, expose a `RestTemplateBuilder` and use the `RestTemplateBuilderConfigurer` to keep what the auto-configuration would do (the example adds connect timeouts of 5 s and read timeouts of 2 s); your own `RestTemplateBuilder` prevents the use of `RestTemplateCustomizer` beans.
