## JMS
- **[from source]** ActiveMQ "Classic": if present and without `broker-url`, it starts an **embedded** broker (VM transport); `spring.activemq.in-memory=false` turns it off; `spring.activemq.broker-url|user|password`; `spring.activemq.pool.*` (needs `org.messaginghub:pooled-jms`); `spring.jms.cache.session-cache-size` (SBR p.372-374). Artemis: `spring.artemis.mode=native|embedded`, `broker-url`, `user`, `password`, `pool.*` (SBR p.374-376).
- **[from source]** JNDI: `java:/JmsXA` and `java:/XAConnectionFactory` by default; `spring.jms.jndi-name` (SBR p.376). Auto-configured `JmsTemplate`; `@JmsListener`; the default listener factory is transactional; `DefaultJmsListenerContainerFactoryConfigurer` reuses the settings; the transacted session can be turned off (SBR p.376-380, 636).

## AMQP / RabbitMQ
- **[from source]** `spring.rabbitmq.host|port|username|password|addresses` (with `addresses`, host/port are ignored; `amqps` turns on SSL) (SBR p.381-382). `AmqpTemplate`/`AmqpAdmin`; `Queue` beans declare queues; template retry is off by default (`spring.rabbitmq.template.retry.enabled|initial-interval`); streams: `spring.rabbitmq.stream.name` (SBR p.383-385).
- **[from source]** `@RabbitListener`; `spring.rabbitmq.listener.type` (simple|direct). **IMPORTANT:** with retry off and an exception in the listener, the message is **redelivered indefinitely**; use `defaultRequeueRejected=false` or throw `AmqpRejectAndDontRequeueException` (SBR p.385-388).
- **[from source]** **Listener retries and redelivery:** listener retries are **disabled by default**; when enabled, the default recoverer is `RejectAndDontRequeueRecoverer` (or your own `MessageRecoverer`, which Boot associates with the default factory); **once the attempts are exhausted, the message is rejected and then discarded or routed to a dead-letter exchange, if the broker is configured for that** (the Reference does not show how to declare a DLX/DLQ); the `RetryTemplate` is customized with a `RabbitRetryTemplateCustomizer` bean. Without retries and with an exception, delivery is repeated indefinitely; two ways out: `defaultRequeueRejected=false` (zero redeliveries) or throwing `AmqpRejectAndDontRequeueException` (the mechanism used when the maximum number of attempts is reached) (SBR p.388). Retries of the **template** (publishing) also come off (`spring.rabbitmq.template.retry.enabled|initial-interval`; `RabbitRetryTemplateCustomizer`) (SBR p.384).
- **[from source, Appendix A]** The container type `spring.rabbitmq.listener.type` is `simple` by default (SBR p.735). Keys `spring.rabbitmq.listener.simple.*`: `retry.enabled` (false), `retry.max-attempts` (3), `retry.initial-interval` (1000ms), `retry.max-interval` (10000ms) (SBR p.734), `retry.multiplier` (1), `retry.stateless` (true) (SBR p.735); `default-requeue-rejected` (no default in the table), `missing-queues-fatal` (true), `consumer-batch-enabled` (false), `de-batching-enabled` (true) (SBR p.734); `acknowledge-mode`, `auto-startup` (true), `batch-size`, `concurrency` (SBR p.733); `max-concurrency`, `prefetch`, `idle-event-interval` (SBR p.734). The `direct` container has the mirror `spring.rabbitmq.listener.direct.*` (`missing-queues-fatal` false; same `retry.*`) (SBR p.733); streams: `spring.rabbitmq.listener.stream.auto-startup` (true) and `native-listener` (false) (SBR p.735). Template: `spring.rabbitmq.template.retry.enabled` (false), `...initial-interval` (1000ms), `...max-attempts` (3), `...max-interval` (10000ms), `...multiplier` (1) (SBR p.737). Others: `spring.rabbitmq.publisher-returns` (false), `publisher-confirm-type`, `requested-channel-max` (2047), `ssl.enabled|verify-hostname (true)|validate-server-certificate (true)|key-store|trust-store` (SBR p.735-736), `cache.connection.mode` (channel) (SBR p.732). [inference] To limit redeliveries without a DLX: enable `listener.simple.retry.*` with `max-attempts` and let the default recoverer reject the message.
- **[from source]** Other Rabbit details: `ConnectionFactoryCustomizer` adjusts the low-level `ConnectionFactory`; `ConnectionNameStrategy` names connections (SBR p.382); `RabbitMessagingTemplate` and `MessageConverter` associated with the `AmqpTemplate`; `RabbitTemplateConfigurer` for more templates; `RabbitStreamTemplate` with `MessageConverter`/`StreamMessageConverter`/`ProducerCustomizer` and `RabbitStreamTemplateConfigurer` (SBR p.384-385); your own listener factories with `SimpleRabbitListenerContainerFactoryConfigurer` or `DirectRabbitListenerContainerFactoryConfigurer` (SBR p.385-386).

## Kafka
- **[from source]** `spring.kafka.bootstrap-servers`, `spring.kafka.consumer.group-id`; a `NewTopic` bean creates a topic at startup; `KafkaTemplate`; `spring.kafka.producer.transaction-id-prefix` configures `KafkaTransactionManager`; `@KafkaListener` (SBR p.388-390). Kafka Streams: Boot auto-configures the `KafkaStreamsConfiguration` bean only if `kafka-streams` is on the classpath AND Kafka Streams is enabled via `@EnableKafkaStreams` (the library on the classpath alone is not enough); enabling requires the application id and bootstrap servers to be defined: the first via `spring.kafka.streams.application-id` (default `spring.application.name`), the second globally or for streams only; `StreamsBuilder` is injected in the `@Bean`; streams start automatically, controlled by `spring.kafka.streams.auto-startup` (SBR p.391-392). Extra properties via `spring.kafka[.admin|.consumer|.producer|.streams].properties[...]`; they **override** what Boot supports; `spring.json.trusted.packages` for `JsonDeserializer` (SBR p.392-394). Tests with `@EmbeddedKafka`: map `spring.kafka.bootstrap-servers` (SBR p.394-396).

- **[from source]** **Kafka in detail:** topic creation via `NewTopic` is ignored if the topic already exists (SBR p.389); the default listener factory uses the `spring.kafka.listener.*` keys and Boot automatically associates `KafkaTransactionManager`, `RecordFilterStrategy`, `CommonErrorHandler`, `AfterRollbackProcessor` and `ConsumerAwareRebalanceListener` beans; `RecordMessageConverter`/`BatchMessageConverter` depending on the listener type (a single `RecordMessageConverter` in a batch listener is wrapped); your own `ChainedKafkaTransactionManager` must be `@Primary` (SBR p.390). Kafka Streams: activation requires `kafka-streams` on the classpath and `@EnableKafkaStreams`, plus application id and bootstrap servers; `spring.kafka.streams.application-id` (default `spring.application.name`), `spring.kafka.streams.auto-startup` (SBR p.391-392). Appendix A: `spring.kafka.streams.application-id` has an empty Default column, but the description points to `spring.application.name` (SBR p.730). Properties without a client type (producer/consumer/admin/streams) are common to all; Boot supports all Kafka properties of HIGH importance, some MEDIUM/LOW and those without a default; the rest go through `.properties[...]` and **override** what Boot supports; `JsonDeserializer`/`JsonSerializer` via `spring.kafka.consumer.value-deserializer`, `spring.json.value.default.type`, `spring.json.trusted.packages`, `spring.json.add.type.headers` (SBR p.392-394). Appendix A (defaults): `spring.kafka.admin.fail-fast` false (SBR p.723); `spring.kafka.consumer.auto-offset-reset` exists, with no default and no semantics in the Reference (SBR p.724); `spring.kafka.consumer.isolation-level` read-uncommitted (SBR p.725); `spring.kafka.listener.type` single, `ack-mode` and `concurrency` with no default (SBR p.726-727); `spring.kafka.listener.missing-topics-fatal` false (SBR p.727). **Redelivery/retry in Kafka:** the Reference does not describe listener retry or DLT (only the associated `CommonErrorHandler`) (SBR p.390); `spring.kafka.producer.retries` exists in Appendix A (SBR p.728). KRaft: 0 occurrences; ZooKeeper only in non-Kafka contexts (SBR p.96).
- **[from source]** **Tests with embedded Kafka (SBR p.394-396):** `@EmbeddedKafka` (`spring-kafka-test` module); three ways to map the broker addresses to `spring.kafka.bootstrap-servers`: system property `EmbeddedKafkaBroker.BROKER_LIST_PROPERTY`, the annotation's `bootstrapServersProperty` attribute, or `spring.kafka.bootstrap-servers=${spring.embedded.kafka.brokers}`.
- **[from source]** **JMS in detail:** `CachingConnectionFactory` by default (`spring.jms.cache.session-cache-size`); native pool with `org.messaginghub:pooled-jms` and `spring.activemq.pool.enabled|max-connections` (or `spring.artemis.pool.*`); `ActiveMQConnectionFactoryCustomizer`; ActiveMQ creates nonexistent destinations (SBR p.373-375). Artemis: `mode` = `embedded` (error if the broker is not on the classpath; requires `artemis-jms-server`) or `native` (local broker with defaults); embedded destinations by list or `JMSQueueConfiguration`/`TopicConfiguration` beans (SBR p.374-376). `@JmsListener`: default factory is **transactional**; with a `JtaTransactionManager` it is associated, otherwise it turns on `sessionTransacted` (and `@Transactional` on the method ties the local transaction to the ack); `DestinationResolver`, `MessageConverter` and `javax.jms.ExceptionListener` beans enter the default factory (SBR p.376-378). Appendix A: `spring.activemq.in-memory` true (SBR p.715); `spring.jms.listener.auto-startup` true, `receive-timeout` 1s (SBR p.721-722).

## RSocket, Integration, WebSocket
- **[from source]** RSocket: CBOR then JSON (Jackson) codecs; server plugged into WebFlux (`spring.rsocket.server.mapping-path`, `transport=websocket`, only with Reactor Netty) or standalone (`spring.rsocket.server.port`); `RSocketRequester.Builder` is prototype (SBR p.396-398). Spring Integration: `spring.integration.poller.*`, `spring.integration.jdbc.initialize-schema`, `spring.integration.rsocket.*` (SBR p.399-400). WebSockets: auto-config for embedded Tomcat/Jetty/Undertow; in a war on a standalone container, the **container is responsible** for the WebSocket configuration; MVC: `spring-boot-starter-websocket` module; reactive: `spring-boot-starter-webflux` + `javax.websocket-api` dependency (groupId `javax.websocket`) (SBR p.401).

## Cache
- **[from source]** Needs `@EnableCaching`; without a library, it uses a simple provider with `ConcurrentHashMap` ("not recommended for production"); detection order: Generic, JCache, EhCache 2.x, Hazelcast, Infinispan, Couchbase, Redis, Caffeine, Cache2k, Simple; `spring.cache.type` forces the provider (use `none` for no-op); `spring.cache.cache-names`; `CacheManagerCustomizer`; do not mix Spring Cache and JCache annotations (SBR p.402-404, 413-414).
- **[from source]** Keys: `spring.cache.jcache.provider`, `spring.cache.jcache.config`, `spring.cache.ehcache.config`, `spring.cache.infinispan.config`, `spring.cache.couchbase.expiration`, `spring.cache.redis.time-to-live` (keep the key prefix), `spring.cache.caffeine.spec` (SBR p.405-413). A cache outside `cache-names` fails at runtime, not at startup (SBR p.413).
- **[from source]** Hazelcast: looks for a client (`ClientConfig`, `spring.hazelcast.config`, `hazelcast-client.*`) and otherwise starts an embedded server; Hazelcast 3 support deprecated (SBR p.414-415).

## Quartz, email, validation, clients
- **[from source]** Quartz: own starter; `JobDetail`/`Trigger`/`Calendar` as beans; memory by default; JDBC with `spring.quartz.job-store-type=jdbc` (`initialize-schema=always` **drops existing tables** on every restart); `@QuartzDataSource`; `spring.quartz.properties.*` (SBR p.415-417).
- **[from source]** Email: `spring.mail.host` creates `JavaMailSender`; some **default SMTP timeouts are infinite**: set `mail.smtp.connectiontimeout`, `mail.smtp.timeout` and `mail.smtp.writetimeout` in `spring.mail.properties`; `spring.mail.jndi-name` takes precedence (SBR p.418-419).
- **[from source]** Method validation with JSR-303 requires `@Validated` on the class (SBR p.419-420).
- **[from source]** `RestTemplate`: there is no single bean; use the auto-configured `RestTemplateBuilder`; HTTP client chosen in order: Apache HttpClient, OkHttp, JDK; customize with `RestTemplateCustomizer` (SBR p.420-427). `WebClient`: use the injected `WebClient.Builder` (stateful; `clone()` for several); connector: Reactor Netty, Jetty RS, Apache HttpClient, JDK; `WebClient.create()` ignores the auto-config (SBR p.427-429). Web Services: `WebServiceTemplateBuilder`, `spring.webservices.wsdl-locations` (SBR p.429-432).
- **[from source]** JTA: embedded Atomikos (`spring-boot-starter-jta-atomikos`; `spring.jta.log-dir`; set a unique `spring.jta.transaction-manager-id` per instance in production), Java EE server or turn it off with `spring.jta.enabled=false`; `nonXaJmsConnectionFactory`/`xaJmsConnectionFactory` (SBR p.433-435).

## IO additions (round 2): cache per provider, Hazelcast, Quartz, email, validation, clients and JTA
- **[from source]** Cache, general rules: Boot only looks for providers if you have not defined a `CacheManager` nor a `CacheResolver` named `cacheResolver`; Geode has its own auto-configuration (separate project); the `spring-boot-starter-cache` starter brings `spring-context-support`, needed for JCache, EhCache 2.x and Caffeine if you declare the dependencies by hand; `CacheManagerCustomizer` only runs if the expected `CacheManager` (e.g. `ConcurrentMapCacheManager`) is the auto-configured one (SBR p.403-405). Warnings: the JSR-107 annotations and Spring Cache's should not be mixed (SBR p.403).
- **[from source]** Providers: **Generic** if there is at least one `Cache` bean (a `CacheManager` wraps them all); **JCache**: `javax.cache.spi.CachingProvider` on the classpath; several providers require `spring.cache.jcache.provider`; `spring.cache.jcache.config`; if the library offers native and JSR-107, Boot prefers JSR-107; `JCacheManagerCustomizer` (SBR p.405-406). Your own `javax.cache.CacheManager` is automatically wrapped in Spring's `CacheManager` and **no additional customization is applied to it** (SBR p.406, TIP). If there is a single `HazelcastInstance` (Boot's general Hazelcast support), it is also reused for the `CacheManager`, **unless** `spring.cache.jcache.config` is specified (SBR p.406, TIP). To customize the underlying (auto-configured) `javax.cache.CacheManager`: `spring.cache.cache-names` creates caches at startup (your own `javax.cache.configuration.Configuration` bean customizes them) and `JCacheManagerCustomizer` beans receive the `CacheManager` for full customization (SBR p.406). **EhCache 2.x** if there is an `ehcache.xml` at the classpath root (`spring.cache.ehcache.config` for another file) (SBR p.406). **Hazelcast** as cache: `spring.cache.type=hazelcast` uses Spring's `CacheManager` and `jcache` uses JCache; with several JCache providers, define the provider (SBR p.407). **Infinispan**: no default location for the file (`spring.cache.infinispan.config`); Boot's support limited to embedded and basic mode (SBR p.407). **Couchbase**: `CouchbaseCacheManager` with `spring.cache.couchbase.expiration` and `CouchbaseCacheManagerBuilderCustomizer` (SBR p.407-408). **Redis**: `RedisCacheManager`, `spring.cache.redis.time-to-live`; the key prefix comes on to avoid collisions between caches (keep it in your own `RedisCacheManager`); your own `RedisCacheConfiguration` changes serialization; `RedisCacheManagerBuilderCustomizer` gives per-cache TTL (SBR p.409-410). **Caffeine**: customization in the order `spring.cache.caffeine.spec`, `CaffeineSpec` bean, `Caffeine` bean; a `CacheLoader<Object, Object>` is associated with the manager (other generics are ignored) (SBR p.411-412). **Cache2k**: `Cache2kBuilderCustomizer` (SBR p.412). **Simple**: `ConcurrentHashMap`, default without a library; `cache-names` restricts (SBR p.413). **None**: `spring.cache.type=none` (no-op for tests; the test slices use this by default via `@AutoConfigureCache`) (SBR p.413-414). Appendix A: `spring.cache.redis.use-key-prefix` true, `cache-null-values` true, `enable-statistics` false (SBR p.677-678).
- **[inference]** TTL per cache for just one of them (e.g. a cache called books): in the Reference, the key `spring.cache.redis.time-to-live` applies to Redis caches in general (SBR p.409); per-cache TTL comes from the `RedisCacheManagerBuilderCustomizer` bean with `entryTtl` by name (SBR p.410).
- **[from source]** Hazelcast (ch. 11.2): first tries to create a **client** (`ClientConfig` bean, `spring.hazelcast.config`, system property `hazelcast.client.config`, `hazelcast-client.xml` and `hazelcast-client.yaml|yml` (SBR p.414), both searched **in the working directory or at the classpath root**); if it cannot create a client, it tries an embedded server (`Config` bean; `spring.hazelcast.config`; otherwise the default locations: `hazelcast.xml` **in the working directory or at the classpath root**, or the YAML equivalent in the same locations; it also checks the system property `hazelcast.config`) (SBR p.414-415); with an instance name it tries to reuse the existing one; Hazelcast 3 deprecated; `HazelcastConfigCustomizer` with `@Order` greater than zero; `@SpringAware` supported; with cache enabled the instance becomes a `CacheManager` (SBR p.414-415).
- **[from source]** Quartz: `JobDetail`, `Calendar` and `Trigger` become part of the `Scheduler`; JDBC requires a `DataSource` (SBR p.415); memory by default (`spring.quartz.job-store-type`, default memory) (SBR p.675); `spring.quartz.jdbc.initialize-schema` (default `embedded`) (SBR p.674) with `always` **drops tables** on every restart (SBR p.416); own script in `spring.quartz.jdbc.schema`; `@QuartzDataSource` and `@QuartzTransactionManager` isolate Quartz from the main `DataSource`/`TransactionManager`; configuration jobs do not overwrite those already saved in the persistent store unless `spring.quartz.overwrite-existing-jobs` (default false) (SBR p.416); an `Executor` bean is **not** associated with the scheduler (use `spring.quartz.properties.*` or `SchedulerFactoryBeanCustomizer`); `QuartzJobBean` jobs receive data through setters (SBR p.416-417).
- **[from source]** Email: `spring.mail.host` + library creates `JavaMailSender` (if one does not exist) (SBR p.418); `spring.mail.*` (`default-encoding` UTF-8, `protocol` smtp, `test-connection` false) (SBR p.678); SMTP timeouts infinite by default in some cases: set `mail.smtp.connectiontimeout`, `mail.smtp.timeout`, `mail.smtp.writetimeout` in `spring.mail.properties`; `spring.mail.jndi-name` takes precedence over the other session settings (SBR p.418-419).
- **[from source]** Validation: method validation (Bean Validation 1.1) is turned on if there is a JSR-303 implementation (e.g. Hibernate Validator) on the classpath, with `javax.validation` constraints on parameters/return and `@Validated` **on the class**; the application's `MessageSource` resolves `{parameters}` in the messages (use your `messages.properties`); then Bean Validation's default interpolation completes (SBR p.419-420).
- **[from source]** `RestTemplate`: three levels of customization: the injected `RestTemplateBuilder` (each call returns a new builder, minimal scope); `RestTemplateCustomizer` (additive, application-wide; the book's example: proxy except for one host); or your own `RestTemplateBuilder` (optionally with `RestTemplateBuilderConfigurer`; without the configurer, the `RestTemplateCustomizer`s stop being used) (SBR p.421-426). `WebClient`: the preconfigured `WebClient.Builder` shares HTTP resources and reflects the server's codecs; the same client as the reactive server shares resources; your own `ClientHttpConnector` gives full control; `WebClientCustomizer` (additive); `WebClient.create()` ignores the auto-config; Jetty as the reactive server requires `jetty-reactive-httpclient` (SBR p.427-429). Web Services: `SimpleWsdl11Definition`/`SimpleXsdSchema` via `spring.webservices.wsdl-locations`; `WebServiceTemplateBuilder` detects the HTTP `WebServiceMessageSender`; timeouts via `HttpWebServiceMessageSenderBuilder` (SBR p.429-432).
- **[from source]** RSocket: server plugged into the WebFlux server only with Reactor Netty (`spring.rsocket.server.mapping-path`, `transport=websocket`) or standalone (`spring.rsocket.server.port`); auto-configured `RSocketMessageHandler`; `RSocketRequester.Builder` (prototype; applies `RSocketConnectorConfigurer` beans); `RSocketStrategiesCustomizer` (codec order by `@Order`) (SBR p.396-398). Integration: `spring-integration-jmx` publishes statistics; `spring-integration-jdbc` can create the schema (`spring.integration.jdbc.initialize-schema=always`); `spring-integration-rsocket` with `spring.rsocket.server.*` and `spring.integration.rsocket.client.host|port|uri` (SBR p.399-400).
- **[from source]** JTA: with a JTA environment detected, it uses `JtaTransactionManager` and "promotes" auto-configured JMS, DataSource and JPA to XA; `spring.jta.enabled=false` keeps local transactions; Atomikos: logs in `transaction-logs` (changed with `spring.jta.log-dir`), `spring.jta.atomikos.properties.*`, unique id per instance (`spring.jta.transaction-manager-id`; by default it is the IP); Java EE server: JNDI `java:comp/UserTransaction`, `java:comp/TransactionManager`; JMS: the primary `ConnectionFactory` is XA; use `nonXaJmsConnectionFactory` (or the alias `xaJmsConnectionFactory`) (SBR p.433-435).
- **POINTER ONLY:** Spring Integration in depth (only Boot's integrations above), broker-specific properties beyond those listed, and STOMP (mentioned in SBR p.372).

## Small Kafka details (round 4, part 2)
- **[from source]** Extra Kafka properties: `spring.kafka.properties[...]`, `spring.kafka.admin.properties[...]`, `spring.kafka.consumer.properties[...]`, `spring.kafka.producer.properties[...]` and `spring.kafka.streams.properties[...]` (with the client key in brackets) pass arbitrary keys to the client; for Spring Kafka's `JsonDeserializer` use `spring.kafka.consumer.value-deserializer`, `spring.kafka.consumer.properties[spring.json.value.default.type]` and `spring.kafka.consumer.properties[spring.json.trusted.packages]`; for the `JsonSerializer`, `spring.kafka.producer.value-serializer` and `spring.kafka.producer.properties[spring.json.add.type.headers]=false` (do not send the type in headers) (SBR p.393-394). Properties defined this way override any item that Boot explicitly supports (SBR p.393-394).
