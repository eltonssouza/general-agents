## Spring Security (defaults)
- **[from source]** With Spring Security on the classpath the web app is protected by default: an in-memory `UserDetailsService` with user `user` and a **random password printed in the log at WARN level** ("for development only"); the category `org.springframework.boot.autoconfigure.security` must log at WARN; `spring.security.user.name`/`password` change the user; form login or HTTP Basic depending on `Accept`; it also applies to Actuator endpoints (SBR p.301-302).
- **[from source]** MVC: a `SecurityFilterChain` bean turns off the default web security (but **not** the `UserDetailsService` nor Actuator security); a `UserDetailsService`/`AuthenticationProvider`/`AuthenticationManager` bean turns off the default user; `EndpointRequest` and `PathRequest` help match Actuator endpoints and static resources (SBR p.302, 642). WebFlux: `SecurityWebFilterChain`/`WebFilterChainProxy` and `ReactiveUserDetailsService` (SBR p.302-303).
- **[from source]** Behind a proxy, requiring HTTPS: `server.tomcat.remoteip.*` (RemoteIpValve) and `http.requiresChannel(...requiresSecure())` (SBR p.643-644). **Either** of the two `remoteip.*` properties turns on the valve (SBR p.643); NATIVE vs FRAMEWORK, `server.tomcat.redirect-context-root=false` and the default of `internal-proxies` are in `references/05` §"Behind a proxy: step by step" (SBR p.580-582, 764). Example of Actuator security with `EndpointRequest` and role `ENDPOINT_ADMIN`: `references/10` (SBR p.446-448).

## OAuth2 and SAML 2.0
- **[from source]** Client: `spring.security.oauth2.client.registration.<id>.*` (`client-id`, `client-secret`, `provider`, `scope`, `redirect-uri`, `authorization-grant-type`...) and `provider.<id>.*` (`authorization-uri`, `token-uri`, `user-info-uri`, `jwk-set-uri`, `issuer-uri`...); `issuer-uri` activates OIDC discovery; providers with defaults: `google`, `github`, `facebook`, `okta`; default callback `/login/oauth2/code/*` (SBR p.304-308).
- **[from source]** `InMemoryOAuth2AuthorizedClientService` is for development only; in production use `JdbcOAuth2AuthorizedClientService` or your own implementation (SBR p.308).
- **[from source]** Resource server: `spring.security.oauth2.resourceserver.jwt.{jwk-set-uri | issuer-uri | public-key-location | audiences}` or `opaquetoken.{introspection-uri, client-id, client-secret}` (SBR p.309-311). **[from source]** Bean alternatives (JWT tokens or *opaque tokens*): `JwtDecoder` (servlet) / `ReactiveJwtDecoder` (reactive) in place of the `jwt.*` properties (SBR p.310); `OpaqueTokenIntrospector` / `ReactiveOpaqueTokenIntrospector` in place of `opaquetoken.*` (SBR p.311). There is no resource server secret-key property in the Reference. **[DATED]** Authorization Server: the text says Spring Security did not implement it and points to `spring-security-oauth2-autoconfigure` (SBR p.311).
- **[from source]** SAML 2.0 relying party: `spring.security.saml2.relyingparty.registration.<id>.*` (signing/decryption credentials, `assertingparty.*`, `singlelogout.*`); default logout `/logout/saml2/slo` (SBR p.311-314). Note: the PDF spells `reponse-url` in one example (SBR p.312-313); check the current spelling in the documentation.

## Spring Session
- **[from source]** Servlet: JDBC, Redis, Hazelcast, MongoDB; reactive: Redis, MongoDB; `spring.session.store-type` (e.g. `jdbc`; `none` turns it off); `spring.session.timeout` (otherwise `server.servlet.session.timeout`); `@Enable*HttpSession` makes the auto-configuration back away (SBR p.314-315).

## Spring for GraphQL
- **[from source]** Starter `spring-boot-starter-graphql` + a transport (web, websocket, webflux, rsocket); schema `*.graphqls`/`*.gqls` in `src/main/resources/graphql/**` (`spring.graphql.schema.locations`, `classpath*:graphql/**/` for modules); schema introspection allowed by default (`spring.graphql.schema.introspection.enabled`) (SBR p.315-317).
- **[from source]** HTTP endpoint `POST /graphql` (`spring.graphql.path`); WebSocket off by default (`spring.graphql.websocket.path` + dependency in servlet); `spring.graphql.cors.*`; RSocket via `spring.graphql.rsocket.mapping`; GraphiQL at `/graphiql` off by default (`spring.graphql.graphiql.enabled`; devtools turns it on); schema printing at `/graphql/schema` (`spring.graphql.schema.printer.enabled`) (SBR p.319-321).
- **[from source]** `@Controller` with `@QueryMapping`/`@Argument`; `RuntimeWiringConfigurer`; `@GraphQlRepository`; `DataFetcherExceptionResolver` (SBR p.317-318, 321).

## Spring HATEOAS
- **[from source]** Auto-configuration replaces `@EnableHypermediaSupport`; `spring-boot-starter-hateoas` is MVC only; by default `application/json` receives `application/hal+json` (`spring.hateoas.use-hal-as-default-json-media-type=false` turns it off) (SBR p.321).

## Security, Session and GraphQL additions (round 2)
- **[from source]** Default web security features (SBR p.301-302): in-memory `UserDetailsService` (or `ReactiveUserDetailsService`) with a single user with a generated password (see `SecurityProperties.User`); form login or HTTP Basic depending on the `Accept` header, **for the whole application, including Actuator endpoints if present**; a `DefaultAuthenticationEventPublisher` (replaceable by an `AuthenticationEventPublisher` bean) (SBR p.301-302). Method-level security: `@EnableGlobalMethodSecurity` (SBR p.301). The configuration is in `SecurityAutoConfiguration` (imports `SpringBootWebSecurityConfiguration`) and `UserDetailsServiceAutoConfiguration` (authentication, relevant even without web); in reactive: `ReactiveSecurityAutoConfiguration` (imports `WebFluxSecurityConfiguration`) (SBR p.302).
- **[from source]** Turning off pieces (SBR p.302): MVC, `SecurityFilterChain` bean (the text of the Security chapter says this does not turn off the `UserDetailsService` nor Actuator security); to also turn off the default user, a `UserDetailsService`, `AuthenticationProvider` or `AuthenticationManager` bean; WebFlux: a `WebFilterChainProxy` bean turns off the default web security and `ReactiveUserDetailsService` or `ReactiveAuthenticationManager` the default user; access rules and combining OAuth2 Client and Resource Server: your own `SecurityWebFilterChain` (SBR p.302). `EndpointRequest` and `PathRequest` generate matchers (in reactive, `ServerWebExchangeMatcher`, e.g. `PathRequest.toStaticResources().atCommonLocations()`) (SBR p.302-303). **Internal divergence [DATED]:** the Actuator chapter says that your own `SecurityFilterChain` makes Boot back away completely, including from the endpoint protection (SBR p.446-448); the parenthetical on p.302 says the opposite. When in doubt, declare explicit rules for the endpoints and for the rest of the application.
- **[from source]** Spring Session (SBR p.314-315): servlet — JDBC, Redis, Hazelcast, MongoDB (Geode via a separate project); reactive — Redis, MongoDB; the auto-configuration makes `@Enable*HttpSession`/`@Enable*WebSession` unnecessary and **backs away** when you use those annotations; with a single module on the classpath it is used automatically, with several choose via `spring.session.store-type` (`none` turns it off); per store, e.g. `spring.session.jdbc.table-name`; `spring.session.timeout`, falling back to `server.servlet.session.timeout` in servlet (SBR p.314-315).
- **[from source]** GraphQL (SBR p.317-321): schema introspection is allowed by default because of tools such as GraphiQL (`spring.graphql.schema.introspection.enabled=false` to avoid exposing it) (SBR p.317); `RuntimeWiringConfigurer` beans receive the `RuntimeWiring.Builder` (scalars, directives, resolvers, `DataFetcher`); a `@Controller` with annotated methods is detected and registered as a `DataFetcher` (SBR p.317); the HTTP endpoint (MVC and WebFlux) is a `RouterFunction` bean with `@Order` 0 (order yours); WebSocket requires `spring-boot-starter-websocket` in servlet (nothing extra in reactive) and `spring.graphql.websocket.path`; `WebInterceptor` bean to read/write headers in the GraphQL context; CORS: `spring.graphql.cors.allowed-origins|allowed-methods|max-age` (SBR p.319); RSocket: `spring.graphql.rsocket.mapping` and the auto-configured `RSocketGraphQlClient.Builder` (SBR p.319-320); errors: `DataFetcherExceptionResolver` beans are invoked in sequence (they resolve the exception into a `GraphQLError`) (SBR p.321).
- **POINTER ONLY:** fine-grained configuration of authorization policies, hardening and application CSRF/CORS (the Reference only covers Boot's defaults); Authorization Server (the Reference points to an external project, SBR p.311).
