# Glossary (BAAS and CE2)

Terms as used in the texts. "BAAS p.N" = PDF page (printed = PDF − 25); "CE2 p.N" = PDF page = printed. Explanations in our own words.

## Agents (BAAS)
- **Intelligent agent**: a self-governing entity that perceives the environment and acts on goals; attributes of reactivity, proactiveness and social ability (BAAS p.60).
- **Self-governance**: deciding and regulating one's own behavior (self-organization, self-regulation, self-adaptation, self-optimization, self-determination) (BAAS p.54).
- **Agency**: the power to act and choose, with decision-making authority, intentionality and responsibility (BAAS p.54-55).
- **Operational, functional, hierarchical autonomy**: acting without direct human intervention; choosing actions for goals according to context; degree of decision-making power in a larger structure (BAAS p.55-56).
- **Deliberative / reactive / hybrid architecture**: plans with explicit knowledge (sensing-planning-execution cycle); maps perception to action; combines reactive and deliberative layers (BAAS p.61-65).
- **Multi-agent system (MAS)**: several autonomous agents that cooperate, coordinate and negotiate (BAAS p.65-70).
- **CWD (coordinator, worker, delegator)**: the book's model: the coordinator manages the flow, workers execute, the delegator assigns and balances load (BAAS p.164).
- **Task Interpreter**: the book's name for the delegator in the role of translating high-level tasks into concrete actions (BAAS p.170).
- **Agent Controller**: external environment that actually executes the tool calls generated by the LLM (BAAS p.134-135).
- **Function calling × tool calling**: the book's distinction between predefined internal functions and interaction with external systems (BAAS p.134).
- **Tool docstring / JSON schema**: two ways of describing a tool to the agent (BAAS p.136-137).
- **Utility (function)**: maps outcomes to real values to compare options (BAAS p.88-89).
- **HTN**: planning that decomposes abstract tasks into subtasks down to primitives (BAAS p.147-148).
- **Meta-reasoning**: monitoring and controlling one's own reasoning (BAAS p.108-110).
- **Self-explanation**: the agent verbalizes the reasons for the decision, for transparency or learning (BAAS p.117-118).
- **Self-modeling**: maintaining an internal representation of goals, beliefs and knowledge (BAAS p.121-122).
- **Backstory**: CrewAI field, merged into the system prompt together with the `role` (BAAS p.169).
- **System prompt**: the agent's persistent configuration layer: role, limits, protocols, decision (BAAS p.179-180).
- **State space / environment modeling**: representation of the situation and the world with static rules and dynamic conditions (BAAS p.192-195).
- **Event-driven update / state transition validation**: reacting to events instead of *polling*; blocking invalid state changes (BAAS p.196-198).
- **Working, long-term, episodic memory**: see BAAS p.199-202.
- **Context hierarchy (global, session, task) and context switching**: BAAS p.202-203.
- **Action limits, decision verification, rollback, monitoring, HITL**: agent safety considerations (BAAS p.237-238).
- **Progressive autonomy**: start restricted and expand with reliability (BAAS p.240).
- **XAI (explainable AI)**: techniques such as attention, saliency and natural-language explanations (BAAS p.216-220).

## Context (CE2)
- **Context (Dey)**: all information that characterizes the situation of entities relevant to the interaction between user and application (CE2 p.5, 7).
- **Char(e), Erel**: characterization of an entity and set of relevant entities; C is the union of Char(e) over Erel (CE2 p.4-5).
- **Context engineering**: a systematic process of designing and optimizing the collection, storage, management and use of context (CE2 p.5).
- **Entropy reduction**: transforming high-entropy context into low-entropy representations the machine understands (CE2 p.3). A metaphor without a measure.
- **Minimal Sufficiency / Semantic Continuity**: principles of collection and storage (CE2 p.9).
- **Self-baking**: the agent digests its own raw context into structured persistent knowledge (CE2 p.13).
- **Context isolation (subagent)**: own window, prompt and permissions per functional unit (CE2 p.12).
- **Lightweight reference**: keeping large content outside the window and exposing only a reference or selected fields (CE2 p.13).
- **Context Toolkit**: Widgets, Interpreters, Aggregators, Services, Discoverers (CE2 p.7).
- **Context-aware × context-cooperative**: reacts to predefined signals × interprets what the user does and collaborates (CE2 p.8).
- **Context selection**: choosing the subset relevant to the current step ("attention before attention") (CE2 p.16).
- **KV cache**: reusing attention keys and values of past tokens to reduce latency and cost (CE2 p.18).
- **Lifelong context**: continuous preservation and updating of context, with four challenges (CE2 p.17-18).
- **Semantic operating system**: the paper's vision for managing context as a system that grows and forgets (CE2 p.18).
