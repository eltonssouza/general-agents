## DataSource
- **[from source]** Embedded databases H2, HSQL and Derby are auto-configured (requires `spring-jdbc`); with several on the classpath, `spring.datasource.embedded-database-connection` chooses (`none` turns it off); `spring.datasource.generate-unique-name=true` gives one database per context (SBR p.323-324). If you configure the URL of an embedded database, turn off the database's auto-shutdown (H2: `DB_CLOSE_ON_EXIT=FALSE`; HSQLDB: no `shutdown=true`) (SBR p.324).
- **[from source]** `spring.datasource.url|username|password|driver-class-name|jndi-name|type` without a URL Boot tries an embedded database; the driver is deduced from the URL (SBR p.324-326). **Pool:** prefers **HikariCP**, then Tomcat, then DBCP2, then Oracle UCP (SBR p.325); prefixes `spring.datasource.hikari.*`, `.tomcat.*`, `.dbcp2.*`, `.oracleucp.*` (SBR p.325). A custom `DataSource` bean turns off the auto-configuration (SBR p.326).
- **[from source]** Datasource name and JNDI (SBR p.689-691): `spring.datasource.jndi-name` set => class, url, username and password are **ignored**; `spring.datasource.name` only applies if generate-unique-name is false (its default: true, SBR p.689), and its default is `testdb` with an embedded database, otherwise null (SBR p.691).
- **[from source]** **Choosing the pool (SBR p.325-326), what matters:** the reason for preferring HikariCP is "performance and concurrency" and, if Hikari is available, it is **always** chosen; then Tomcat, then DBCP2, and Oracle UCP only if none of the three exists. **NOTE:** with `spring-boot-starter-jdbc` or `spring-boot-starter-data-jpa` you get HikariCP automatically as a dependency. `spring.datasource.type` bypasses the algorithm and chooses the pool; it is **"especially important" when the application runs in a Tomcat container, because `tomcat-jdbc` is provided by default** by the container. Other pools are configured by hand with `DataSourceBuilder`, which supports: HikariCP, the Tomcat pool, Commons DBCP2, Oracle UCP and `OracleDataSource`, Spring's `SimpleDriverDataSource`, H2's `JdbcDataSource`, PostgreSQL's `PGSimpleDataSource` and C3P0 (SBR p.326). Tomcat pool example (SBR p.325): `spring.datasource.tomcat.max-wait=10000` (waits 10000 ms for a connection before throwing an exception), `spring.datasource.tomcat.max-active=50`, `spring.datasource.tomcat.test-on-borrow=true` (validates the connection when borrowing). To create the pool Boot checks that the driver class is loadable: if you define `driver-class-name`, the class must exist on the classpath (SBR p.325). JNDI: `spring.datasource.jndi-name` replaces url/username/password (e.g. `java:jboss/datasources/customers`) (SBR p.326). `NamedParameterJdbcTemplate` reuses the same `JdbcTemplate`; if there is more than one `JdbcTemplate` without a primary candidate, it is **not** auto-configured (SBR p.328). [inference] "WAR on external Tomcat" scenario: by the algorithm (Hikari always wins if available), with the starter the application's Hikari is the one chosen; the book's warning weighs in when Hikari is **not** on the application's classpath (e.g. excluded), since the container's `tomcat-jdbc` is then chosen; to avoid depending on detection, fix `spring.datasource.type` (SBR p.325-326).
- **[from source, how-to]** Custom DataSource: `@ConfigurationProperties("app.datasource")` + `DataSourceBuilder`; with Hikari the key is `jdbc-url` (not `url`) unless you use your own `DataSourceProperties` (`app.datasource.configuration.maximum-pool-size`) (SBR p.603-610). Two DataSources: mark one `@Primary` (including the `DataSourceProperties` used by the initializer) (SBR p.610-615).
- **[from source]** `JdbcTemplate`/`NamedParameterJdbcTemplate` auto-configured; `spring.jdbc.template.max-rows` (SBR p.326-328).

## JPA / Spring Data
- **[from source]** Entities by scanning the auto-configuration packages (`@Entity`, `@Embeddable`, `@MappedSuperclass`); `@EntityScan` and `@EnableJpaRepositories` adjust this; Spring Data repositories; bootstrap modes `default|deferred|lazy` (`spring.data.jpa.repositories.bootstrap-mode`) (SBR p.328-331).
- **[from source]** `spring.jpa.hibernate.ddl-auto`: default `create-drop` **only** if the database is embedded and no schema manager (Flyway/Liquibase) takes care of the DataSource; `none` in the other cases; values `none|validate|update|create|create-drop` (SBR p.617, 629). `spring.jpa.properties.*` passes properties to the provider **without relaxed binding** (exact names, e.g. `hibernate.jdbc.batch_size`) (SBR p.618). `HibernatePropertiesCustomizer` takes precedence over the auto-configuration (SBR p.618).
- **[from source]** `spring.jpa.open-in-view`: in a web app Boot registers `OpenEntityManagerInViewInterceptor` (lazy loading in views); `false` turns it off (SBR p.333).
- **[from source, how-to]** Naming strategy: physical `CamelCaseToUnderscoresNamingStrategy` by default (`TelephoneNumber` → `telephone_number`); `spring.jpa.hibernate.naming.physical-strategy|implicit-strategy` (SBR p.618-620). A custom EMF loses the `spring.jpa.hibernate.*` customizations (SBR p.625). `persistence.xml` is not used by default (SBR p.626).
- **[from source]** H2 console: auto-configured if servlet + H2 + devtools; `spring.h2.console.enabled`, `spring.h2.console.enabled` turns the console on (SBR p.334; the default false is in Appendix A, SBR p.695); `spring.h2.console.path` (default `/h2-console`); Appendix A: `spring.h2.console.settings.web-allow-others` (remote access to the console; default false), `settings.trace` (trace output; default false) and `settings.web-admin-password` (password for preferences and tools; no default) (SBR p.696); **development only**, and do not leave `enabled=true` in production (SBR p.334); behind Spring Security it requires CSRF turned off and `X-Frame-Options: SAMEORIGIN` for the console (SBR p.334-336).
- **[from source]** jOOQ: `DSLContext` auto-configured; `spring.jooq.sql-dialect` (open-source dialects only) (SBR p.336-339). R2DBC: `spring.r2dbc.url|username|password`; `ConnectionFactory` makes the JDBC DataSource back off; `DatabaseClient` (SBR p.339-343).

## Database initialization (how-to)
- **[from source]** Recommendation: **a single** schema mechanism (SBR p.628). Scripts: `schema.sql`/`data.sql` (`optional:classpath*:`), `spring.sql.init.schema-locations|data-locations|platform|mode|continue-on-error`; by default only on an in-memory embedded database (`mode=embedded`); `spring.jpa.defer-datasource-initialization=true` runs the scripts after Hibernate (SBR p.629-630). **Do not mix** SQL scripts with Flyway/Liquibase (support will be removed) (SBR p.630).
- **[from source]** Flyway (`flyway-core`; `V<VERSION>__<NAME>.sql` in `classpath:db/migration`; `spring.flyway.locations`, `{vendor}`; test migrations in `src/test/resources/db/migration`); Liquibase (`liquibase-core`; `db/changelog/db.changelog-master.yaml` by default; `spring.liquibase.change-log`); dedicated datasource via `@FlywayDataSource`/`@LiquibaseDataSource` (SBR p.631-634). Spring Batch: `spring.batch.jdbc.initialize-schema` (SBR p.630).
- **[from source]** Quartz: `spring.quartz.job-store-type=jdbc`; the default scripts **drop existing tables** at every restart when `initialize-schema=always` (SBR p.415-416).

## NoSQL (keys and defaults from the text)
- **[from source]** Redis: Lettuce by default (Jedis optional); `spring.redis.host|port|database|username|password` (default `localhost:6379`) (SBR p.345-346; keys and defaults in Appendix A, SBR p.702-704). Page 635 does not list the properties: it only covers swapping Lettuce for Jedis. **Pool (prefixes spring.redis.lettuce.pool and spring.redis.jedis.pool, Appendix A, SBR p.702-704; the Lettuce and Jedis pool keys are parallel, with the same defaults):** the pool is auto-configured if `commons-pool2` is on the classpath (SBR p.346) and `pool.enabled` turns itself on under that condition; with Jedis the pool is implicitly enabled in sentinel mode and `jedis.pool.enabled` only applies to a single node (SBR p.702-703); `max-active` default 8 (negative = no limit); `max-idle` default 8 (negative = unlimited); `max-wait` default `-1ms` (negative = blocks indefinitely when the pool is exhausted; otherwise throws an exception after the time); `min-idle` default 0 and **only has an effect if it and `time-between-eviction-runs` are positive**; a positive `time-between-eviction-runs` starts the thread that evicts idle connections, otherwise there is no eviction and it has no published default (SBR p.703-704). MongoDB: default `mongodb://localhost/test`; `spring.data.mongodb.uri` or `host|port|database|username|password`; a custom `MongoClientSettings` makes the `spring.data.mongodb.*` properties be ignored; embedded via `de.flapdoodle` (SBR p.347-352). Neo4j: `spring.neo4j.uri` (default: server at `localhost:7687` with the Bolt protocol) and `authentication.*`; in reactive mode you define the `ReactiveNeo4jTransactionManager` (SBR p.352-356). Detail (SBR p.355-356): the `spring-boot-starter-data-neo4j` starter enables repositories **and** transaction management; with Project Reactor on the classpath the reactive style is also auto-configured (`ReactiveNeo4jTemplate`), but **a `ReactiveTransactionManager` is not auto-configured** in the reactive application: define a `@Bean` `ReactiveNeo4jTransactionManager` yourself, built with the `Driver` and a `ReactiveDatabaseSelectionProvider`, in a `@Configuration(proxyBeanMethods = false)` class; repositories and entities are found by scanning the auto-configuration package(s), adjustable with `@EnableNeo4jRepositories` and `@EntityScan`.
- **[from source]** Elasticsearch: `spring.elasticsearch.uris` (default `localhost:9200`); the `RestHighLevelClient` auto-configuration is **deprecated** [DATED] (SBR p.358). Cassandra: `spring.data.cassandra.keyspace-name|contact-points|local-datacenter` (port 9042) (SBR p.361-362). Couchbase: `spring.couchbase.connection-string|username|password`, `spring.data.couchbase.bucket-name` (SBR p.364-365). LDAP: `spring.ldap.urls|username|password`; embedded UnboundID (SBR p.368-370). InfluxDB: `spring.influx.url` (SBR p.370-371). Solr: client at `localhost:8983/solr` (SBR p.357).
- **[from source]** `spring.data.*.repositories.enabled|type` turns repositories on/off (useful when JPA and Mongo coexist) (SBR p.626).

## Data additions (round 2): JPA, JDBC, jOOQ, R2DBC and NoSQL in detail
- **[from source]** Embedded: the embedded database requires `spring-jdbc` (comes transitively in the JPA starter) (SBR p.324). `spring.datasource.generate-unique-name`: the NOTE on SBR p.323 says that, without it, the same embedded database is reused by the whole test suite, even with several contexts, and tells you to set it to `true` for one database per context; Appendix A (SBR p.689) lists the default `true`; treat the discrepancy as an editing inconsistency [DATED]. In the reactive version: `spring.r2dbc.generate-unique-name` (Appendix A p.700, default false) (SBR p.342).
- **[from source]** JPA: Boot does not use `persistence.xml`, it scans the auto-configuration packages (SBR p.328). With `deferred`/`lazy` bootstrap do not access the JPA infrastructure before the context bootstrap ends: use `SmartInitializingSingleton` and, in JPA components that are beans (e.g. converters), `ObjectProvider` to defer dependencies (SBR p.331). Spring Data Envers: if available, JPA repositories support Envers queries; extend `RevisionRepository` (SBR p.332).
- **[from source]** `ddl-auto`: by default table creation only happens with an embedded database; `hibernate.hbm2ddl.auto` is Hibernate's internal name and is set via `spring.jpa.properties.*` (the prefix is removed; e.g. `spring.jpa.properties.hibernate[globally_quoted_identifiers]=true`); DDL execution/validation is deferred until the `ApplicationContext` is up; `spring.jpa.generate-ddl` is **not used** if the Hibernate auto-configuration is active, because `ddl-auto` is finer-grained (SBR p.332-333).
- **[from source]** R2DBC with an embedded database (`r2dbc-h2`, no connection URL): in tests the same database is reused by the whole suite, regardless of the number of contexts; for a separate embedded database per context, set `spring.r2dbc.generate-unique-name` to true (unique name per database) (SBR p.342). With a `ConnectionFactory` bean, the JDBC `DataSource` auto-configuration backs off; to keep it, `@Import(DataSourceAutoConfiguration.class)` (SBR p.342).
- **[from source]** Spring Data JDBC: auto-configured with the `spring-boot-starter-data-jdbc` starter; to control it, `@EnableJdbcRepositories` or a subclass of `AbstractJdbcConfiguration` (SBR p.333-334). H2 console behind Spring Security: example `SecurityFilterChain` with `PathRequest.toH2Console()`, CSRF turned off and `frameOptions().sameOrigin()` (SBR p.334-335). Appendix A (SBR p.696): `spring.jdbc.template.fetch-size` (rows fetched at a time; `-1` = JDBC driver default; default -1), `spring.jdbc.template.max-rows` (maximum rows; `-1` = driver default; default -1), `spring.jdbc.template.query-timeout` (no default; without a duration suffix, seconds).
- **[from source]** jOOQ: the `jooq-codegen-maven` plugin needs no `<version>` with `spring-boot-starter-parent` and can use Boot version variables (e.g. `h2.version`); the dialect is detected from the `DataSource` and, if not detected, uses `DEFAULT`; `DefaultConfigurationCustomizer` runs before creating the `org.jooq.Configuration` and takes precedence over the auto-configuration; a custom `org.jooq.Configuration` gives full control (SBR p.336-339).
- **[from source]** R2DBC: at least the URL; what is in the URL takes precedence over the individual properties; without giving a driver class (discovery of the `ConnectionFactory`); `ConnectionFactoryOptionsBuilderCustomizer` (bean) adjusts connection options you do not want to put in the central configuration: syntax `@Bean ConnectionFactoryOptionsBuilderCustomizer c() { return (builder) -> builder.option(ConnectionFactoryOptions.PORT, 5432); }` (changes the port; the rest comes from the application configuration) (SBR p.340; Kotlin on p.341). PostgreSQL: the same bean with `builder.option(PostgresqlConnectionFactoryProvider.OPTIONS, options)`, where `options` is a `Map<String, String>` with `lock_timeout` = `30s` and `statement_timeout` = `60s` (SBR p.341; Kotlin version on p.342). With a `ConnectionFactory` bean, the JDBC `DataSource` **backs off**, and `@Import(DataSourceAutoConfiguration.class)` reactivates it (at your own risk of blocking JDBC in a reactive app) (SBR p.342). `DatabaseClient` auto-configured; R2DBC repositories analogous to the JPA ones (SBR p.343-344).
- **[from source]** Redis: starter `spring-boot-starter-data-redis` (Lettuce by default; serves traditional and reactive apps; there is a `-reactive` one for consistency); inject `RedisConnectionFactory`, `StringRedisTemplate` or `RedisTemplate`; customize with `LettuceClientConfigurationBuilderCustomizer`, `ClientResourcesBuilderCustomizer`, `JedisClientConfigurationBuilderCustomizer` or `RedisStandaloneConfiguration`/`RedisSentinelConfiguration`/`RedisClusterConfiguration` beans; a bean of your own replaces the default (except `RedisTemplate`, whose exclusion is by the **name** `redisTemplate`); pool only if `commons-pool2` is on the classpath (SBR p.345-346).
- **[from source]** MongoDB: starters `spring-boot-starter-data-mongodb` and `-reactive`; a custom `MongoClientSettings` is used unchanged and the `spring.data.mongodb.*` properties are **ignored**; `MongoClientSettingsBuilderCustomizer` fine-tunes; `spring.data.mongodb.uri` accepts replicas; default port 27017; in the reactive driver SSL requires Netty; repositories and documents by scanning (`@EnableMongoRepositories`, `@EntityScan`) (SBR p.347-351). Embedded Mongo: dependency `de.flapdoodle.embed.mongo` and `spring.mongodb.embedded.version`; an unreachable version causes a download error, fixable with `DownloadConfigBuilderCustomizer`; without a configured port it uses a random port (0 = random), and the output goes to the logger `org.springframework.boot.autoconfigure.mongo.embedded.EmbeddedMongo` (SBR p.351-352).
- **[from source]** Neo4j: `Driver` auto-configured (default `localhost:7687`, Bolt); `spring.neo4j.uri` and `spring.neo4j.authentication.*`; `ConfigBuilderCustomizer` fine-tunes; supports classic and reactive repositories (`Neo4jTemplate`/`ReactiveNeo4jTemplate`); in the reactive style the `ReactiveTransactionManager` is **not** auto-configured: the data starter enables repositories and transactions, but the reactive application must declare the bean `ReactiveNeo4jTransactionManager(Driver, ReactiveDatabaseSelectionProvider)` (SBR p.352-356, bean on p.356).
- **[from source]** Elasticsearch: low-level and high-level REST clients and `ReactiveElasticsearchClient`; `spring.elasticsearch.uris|socket-timeout|username|password`; `RestClient` auto-configured if `elasticsearch-rest-client` is present; `RestClientBuilderCustomizer`; `Sniffer` if `elasticsearch-rest-client-sniffer` is present (`spring.elasticsearch.restclient.sniffer.interval|delay-after-failure`); reactive: `spring.elasticsearch.webclient.max-in-memory-size`, a custom `ClientConfiguration` for full control; `ElasticsearchRestTemplate` requires the `RestHighLevelClient`; custom templates must be named `elasticsearchTemplate`/`reactiveElasticsearchTemplate`; `spring.data.elasticsearch.repositories.enabled=false` turns it off (SBR p.358-361).
- **[from source]** Cassandra: `CassandraTemplate` or `CqlSession`; default port 9042 (`spring.data.cassandra.port`); the driver's `application.conf` is not read by default (`spring.data.cassandra.config`), and `spring.data.cassandra.*` takes precedence over the file; `DriverConfigLoaderBuilderCustomizer`/`CqlSessionBuilderCustomizer`; the builder is mutable (inject a fresh copy per session); repositories require `@Query` on finders (SBR p.361-364). Couchbase: `ClusterEnvironment` via `spring.couchbase.env.*` (e.g. `timeouts.connect`, `ssl.key-store`) and `ClusterEnvironmentBuilderCustomizer`; `CouchbaseTemplate` requires `CouchbaseClientFactory` (cluster + `spring.data.couchbase.bucket-name`); replaceable bean names `couchbaseMappingContext`, `couchbaseCustomConversions`, `couchbaseTemplate` (SBR p.364-367).
- **[from source]** LDAP: starter `spring-boot-starter-data-ldap` or `spring-ldap-core`; `spring.ldap.urls|username|password|base|base-environment`; `DirContextAuthenticationStrategy` associated with the `LdapContextSource`; a custom `ContextSource` (e.g. `PooledContextSource`) must be `@Primary`; embedded LDAP (UnboundID, `spring.ldap.embedded.base-dn`, several entries with index `[0]`/`[1]` in properties; random port; `schema.ldif` or `spring.ldap.embedded.ldif`; validation `spring.ldap.embedded.validation.enabled`) (SBR p.368-370). InfluxDB: `spring.influx.url|user|password`; `InfluxDbOkHttpClientBuilderProvider` and `InfluxDbCustomizer` (SBR p.370-371).
- **POINTER ONLY:** Spring Data for Apache Geode/GemFire (mentioned, no configuration; SBR p.344-345) and the list of properties specific to each driver (consult Appendix A via `sbr_lookup.py --prop`).

## Round 4 additions: data how-tos, multiple JPA and database initialization (SBR p.603-638)
- **[from source]** Custom DataSource (SBR p.603-610): define a `@Bean` of the type; Boot reuses it wherever needed, including in database initialization; to externalize it, bind it to a prefix (e.g. `app.datasource.url`, `app.datasource.pool-size`) (SBR p.603-604). `DataSourceBuilder` creates one of the standard DataSources that is on the classpath and detects the driver from the JDBC URL (SBR p.604). Gotcha: since the pool type is not exposed, the metadata does not generate keys for your DataSource (no IDE autocompletion) and, **with Hikari on the classpath, `url` does not work**: use `app.datasource.jdbc-url` (SBR p.606). To force the type, use `DataSourceBuilder.create().type(HikariDataSource.class)` and return the concrete type (SBR p.606-607). To keep a single namespace, redefine a `DataSourceProperties` on your prefix (annotated with `@Primary`) and create the pool with `initializeDataSourceBuilder().type(...)` bound to `app.datasource.configuration` (e.g. `app.datasource.configuration.maximum-pool-size=30`); `DataSourceProperties` handles the `url`/`jdbcUrl` translation (SBR p.607-609). The Hikari-specific keys live under `spring.datasource.hikari`; in this pattern, `app.datasource.type` has no effect because the `type()` in the code overrides it (SBR p.610).
- **[from source]** Two DataSources (SBR p.610-615): apply the same tricks and mark one as `@Primary`, because several auto-configurations expect to obtain a DataSource by type; when you create your own, the auto-configuration backs off (SBR p.610). The example uses Hikari for the first (`app.datasource.first.configuration.maximum-pool-size`) and `BasicDataSource` (Commons DBCP2) for the second (`app.datasource.second.max-total`), each with its own `DataSourceProperties` and `@Qualifier` when necessary (SBR p.613-615).
- **[from source]** Repositories and entities (SBR p.616-617): Boot locates Spring Data `@Repository` and `@Entity` by scanning the auto-configuration packages (the main class's package and subpackages); for more control use Spring Data's `@Enable…Repositories` or `@EntityScan` (e.g. `@EntityScan(basePackageClasses = City.class)`) (SBR p.616). `spring.jpa.hibernate.ddl-auto` is a special case: default `create-drop` if there is an embedded database and no schema manager (Liquibase/Flyway), and `none` in all other cases; the dialect is detected by the provider, but can be fixed with `spring.jpa.database-platform` (SBR p.617).
- **[from source]** JPA/Hibernate properties (SBR p.617-618): everything in `spring.jpa.properties.*` is passed on as a JPA property (without the prefix) when creating the local `EntityManagerFactory`; Boot **does not apply relaxed binding** to these keys, so they must have the provider's exact name (for Hibernate's batch size use `spring.jpa.properties.hibernate.jdbc.batch_size`; `batchSize` or `batch-size` do not work). For advanced tuning register a `HibernatePropertiesCustomizer` bean, called before creating the `EntityManagerFactory` and taking precedence over the auto-configuration (SBR p.618).
- **[from source]** Names in Hibernate (SBR p.618-620): physical and implicit strategies in `spring.jpa.hibernate.naming.physical-strategy` and `spring.jpa.hibernate.naming.implicit-strategy`, or via `PhysicalNamingStrategy`/`ImplicitNamingStrategy` beans. By default the physical strategy is `CamelCaseToUnderscoresNamingStrategy`: dots and camel case become underscores and table names come out in lowercase (entity `TelephoneNumber` becomes table `telephone_number`) (SBR p.618). For mixed-case identifiers, define a `CamelCaseToUnderscoresNamingStrategy` bean overriding `isCaseInsensitive` to false, or go back to the Hibernate 5 default with `PhysicalNamingStrategyStandardImpl` (property or bean) (SBR p.618-620).
- **[from source]** Second-level cache and DI in Hibernate (SBR p.620-622): for JCache include `hibernate-jcache` and register a `HibernatePropertiesCustomizer` that puts the application's `CacheManager` in `ConfigSettings.CACHE_MANAGER` (separate instances can also be used) (SBR p.620-621). By default Boot registers a `BeanContainer` based on the `BeanFactory`, so that converters and entity listeners use dependency injection; to turn it off or adjust it, a `HibernatePropertiesCustomizer` that removes or changes the `hibernate.resource.beans.container` property (SBR p.621-622).
- **[from source]** Custom and multiple `EntityManagerFactory` (SBR p.622-626): a `@Bean` named `entityManagerFactory` makes the auto-configuration back off (SBR p.622). For several DataSources use one `LocalContainerEntityManagerFactoryBean` per DataSource, with their own `JpaProperties` (e.g. prefix `app.jpa.first`), `EntityManagerFactoryBuilder`, `packages(Order.class)` and `persistenceUnit("firstDs")` (SBR p.622-624). When you create the `LocalContainerEntityManagerFactoryBean` you lose the auto-configuration's customizations: the `spring.jpa.hibernate.*` properties (naming, DDL) are **not** applied and must be configured by you; each factory needs a `JpaTransactionManager` (or a JTA manager that covers both); with Spring Data, `@EnableJpaRepositories(basePackageClasses = Order.class, entityManagerFactoryRef = "firstEntityManagerFactory")` per repository package (SBR p.625-626). Boot does not look for `META-INF/persistence.xml`; to use it define a `LocalEntityManagerFactoryBean` bean with id `entityManagerFactory` and the persistence unit name (SBR p.626).
- **[from source]** Other data how-tos (SBR p.626-628): JPA and Mongo together may require `@EnableJpaRepositories` and `@EnableMongoRepositories` with the location; the flags `spring.data.*.repositories.enabled` and `spring.data.*.repositories.type` turn off auto-configured repositories (e.g. turn off Mongo repositories while keeping the `MongoTemplate`); the same goes for Elasticsearch, Solr and others (SBR p.626). Spring Data web support: `spring.data.web.*`; with Spring Data REST use `spring.data.rest.*` and, to go further, a `RepositoryRestConfigurer` bean (without an order it runs **after** Boot's internal one; if you order it, use a value greater than 0) (SBR p.627). A component used by JPA must be initialized before it: Boot takes care of this for what is auto-configured (e.g. Flyway); for your own, extend `EntityManagerFactoryDependsOnPostProcessor` (example: dependency of the `elasticsearchClient` bean on Hibernate Search) (SBR p.627-628). jOOQ with several DataSources: one `DSLContext` per DataSource, reusing `JooqExceptionTranslator` and `SpringTransactionProvider` (SBR p.628).
- **[from source]** Initialization via JPA/Hibernate (SBR p.629): `spring.jpa.generate-ddl` (boolean, provider-independent) and `spring.jpa.hibernate.ddl-auto` (values `none`, `validate`, `update`, `create`, `create-drop`). An embedded database is detected by the connection type and the JDBC URL; only `hsqldb`, `h2` and `derby` are candidates. Be careful when switching from in-memory to a "real" database: do not assume tables and data in the new environment. The logger `org.hibernate.SQL` shows schema creation (turned on automatically in debug mode). An `import.sql` file at the classpath root is executed at startup when Hibernate creates the schema from scratch (`ddl-auto` equal to `create` or `create-drop`); it is a Hibernate feature, useful in demos/tests and usually undesirable in production (SBR p.629).
- **[from source]** Basic SQL scripts (SBR p.629-630): load `optional:classpath*:schema.sql` and `optional:classpath*:data.sql` (JDBC `DataSource` or R2DBC `ConnectionFactory`), with locations in `spring.sql.init.schema-locations` and `spring.sql.init.data-locations`; the `optional:` prefix allows starting without the files (remove it to fail when they are missing). `schema-${platform}.sql` and `data-${platform}.sql` are also processed, with `${platform}` = `spring.sql.init.platform` (e.g. hsqldb, h2, oracle, mysql, postgresql). By default it only initializes an in-memory embedded database; `spring.sql.init.mode=always` initializes any type and `never` turns it off. Fail-fast is on (an error in the script prevents startup); adjust with `spring.sql.init.continue-on-error`. The scripts run before creating the `EntityManagerFactory`; `spring.jpa.defer-datasource-initialization=true` defers them until after Hibernate (combining several initialization technologies is not recommended). Only `--` and `/* */` are accepted as comments. With Flyway or Liquibase, use them alone (SBR p.629-630).
- **[from source]** Spring Batch: embedded per-platform scripts executed at startup (by default on an embedded database); `spring.batch.jdbc.initialize-schema=always` turns it on on any database and `never` turns it off (SBR p.630). Batch datasource: annotate the `@Bean` with `@BatchDataSource` (and mark the other `@Primary`); for more control, `BatchConfigurer`; `@EnableBatchProcessing` activates the auto-configuration, which runs all the Jobs in the context at startup (`JobLauncherApplicationRunner`) and `spring.batch.job.names` (list of patterns) restricts which ones; the job repository requires a real database (it can be in-memory) (SBR p.637-638).
- **[from source]** Flyway (SBR p.631-633): `flyway-core` on the classpath; scripts `V<VERSION>__<NAME>.sql` (version with underscores, such as `1` or `2_1`) in `classpath:db/migration`; `spring.flyway.locations` accepts a list of `classpath:` and `filesystem:` (e.g. `classpath:db/migration,filesystem:/opt/migration`) and the `{vendor}` marker chooses the directory by database (e.g. `db/migration/mysql`). Java migrations via `JavaMigration` beans; `FlywayProperties` covers most options; for more control a `FlywayConfigurationCustomizer` bean; Boot calls `Flyway.migrate()` and a `FlywayMigrationStrategy` replaces that. SQL callbacks live in `classpath:db/migration`; Java callbacks are `Callback` beans orderable with `@Order`/`Ordered` (the deprecated `FlywayCallback` does not coexist with `Callback`). By default it uses the `@Primary` DataSource; another DataSource with `@FlywayDataSource` (and, if there are two, mark the other `@Primary`); or Flyway's native DataSource with `spring.flyway.url`/`spring.flyway.user`/`password` (defining `url` or `user` is enough; the missing ones fall back to the equivalent `spring.datasource`). Test-only migrations in `src/test/resources/db/migration` (e.g. `V9999__test-data.sql`, executed after the production ones and outside the jar); `spring.flyway.locations` per profile (e.g. `application-dev.properties` with `classpath:/db/migration,classpath:/dev/db/migration`) (SBR p.631-633).
- **[from source]** Liquibase (SBR p.632-634): `liquibase-core` on the classpath; runs at startup **and before tests**, controllable via `spring.liquibase.enabled` with distinct values in the main and test configuration (you cannot use two mechanisms, such as Liquibase in the app and JPA in the tests); default master changelog `db/changelog/db.changelog-master.yaml` (change with `spring.liquibase.change-log`; accepts YAML, JSON, XML and SQL); `@Primary` DataSource by default, `@LiquibaseDataSource` for another, or the native one with `spring.liquibase.url`/`user` (SBR p.632-633). Test-only data: a test changelog that includes the production one and adds a `changeSet` with `runOrder: "last"`, pointed to by `spring.liquibase.change-log` in `application-test.properties` and activated with `@ActiveProfiles("test")`; it does not go into the uber jar nor the image (SBR p.633-634).
- **[from source]** Dependency on an initialized database (SBR p.634-635): Boot detects as initializers `DataSourceScriptDatabaseInitializer`, `EntityManagerFactory`, `Flyway`, `FlywayMigrationInitializer`, `R2dbcScriptDatabaseInitializer` and `SpringLiquibase`, and as dependents `AbstractEntityManagerFactoryBean` and `EntityManagerFactory` (unless `spring.jpa.defer-datasource-initialization` is true), `DSLContext`, `JdbcOperations` and `NamedParameterJdbcOperations`. To detect others: `DatabaseInitializerDetector` or `DependsOnDatabaseInitializationDetector` in `META-INF/spring.factories`, or annotate the class/`@Bean` with `@DependsOnDatabaseInitialization` (SBR p.634-635).
- **[from source]** Redis with Jedis instead of Lettuce: exclude `lettuce-core` (`io.lettuce`) from `spring-boot-starter-data-redis` and include `redis.clients:jedis`; Boot manages both versions (SBR p.635-636). JMS without transacted sessions: with `DefaultJmsListenerContainerFactoryConfigurer` configure the factory and call `setTransactionManager(null)` and `setSessionTransacted(false)`; your own `JmsListenerContainerFactory` is already non-transacted by default (SBR p.636-637).
- **[from source]** Actuator (how-to): `management.server.port` and `management.server.address` change the port/address; in a standalone app the default port is the same as the main one (SBR p.638). Hot swapping: devtools is the recommended approach and watches the classpath, so static resources need to be "built" (Eclipse: on save; IntelliJ: Make Project); because of the default exclusions, static resources trigger LiveReload but not restart; `addResources` in the plugins lets you load static resources directly from the source; template caches: `spring.thymeleaf.cache`, `spring.freemarker.cache` and `spring.groovy.template.cache` to false (configured automatically by devtools) (SBR p.644-645). Tests with Spring Security: `@WithMockUser(roles = "ADMIN")` with `@WebMvcTest` and `MockMvc` (SBR p.646-647); Testcontainers: `@Testcontainers` and `@Container` in a `@SpringBootTest` class (example with Neo4j), and `@DynamicPropertySource` with a static method that uses `registry.add` binds the beans to the container: `registry.add("spring.neo4j.uri", neo4j::getBoltUrl)` (SBR p.649). The Docker container starts before any test, if Docker is running locally, and in most cases you need to configure the application with the container's IP/port (SBR p.648). Kotlin: the `@Container` (`Neo4jContainer<*>`) and the `@DynamicPropertySource` go in a `companion object`, and the value comes from `registry.add("spring.neo4j.uri") { neo4j.boltUrl }` (SBR p.648, 650). Result: the Neo4j beans talk to the Neo4j in the container managed by Testcontainers (SBR p.650). There is an example for Neo4j only (image `neo4j:5`) (SBR p.647-650).

## LDAP and in-memory LDAP server (embedded LDAP), round 4 detail
- **[from source]** The **embedded in-memory LDAP** server (UnboundID) is auto-configured "for testing purposes" (not for production): add the `unboundid-ldapsdk` dependency and declare `spring.ldap.embedded.base-dn` (SBR p.369). Several `base-dn` are possible; since DNs usually contain commas, the notation matters: in YAML use a list; in `.properties` include the index in the name (`spring.ldap.embedded.base-dn[0]` and `[1]`) (SBR p.370).
- **[from source]** By default the embedded LDAP starts on a **random port** and triggers the normal LDAP support; **you do not need to define `spring.ldap.urls`** (SBR p.370). If a `schema.ldif` exists on the classpath it initializes the server; for another resource use `spring.ldap.embedded.ldif` (SBR p.370). By default a standard schema validates the LDIF files; `spring.ldap.embedded.validation.enabled` turns validation off entirely and `spring.ldap.embedded.validation.schema` defines custom attribute types or object classes (SBR p.370).
- **[from source]** Common use: Spring LDAP repositories with `@EnableLdapRepositories` and `spring.ldap.base-environment` (JNDI environment properties) (SBR p.368); inject the `LdapTemplate` into a component, whose example calls `findAll` (SBR p.369). `@DataLdapTest` tests use the embedded LDAP if available (SBR p.200-201).
