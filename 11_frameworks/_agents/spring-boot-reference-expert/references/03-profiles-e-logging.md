# 03 — Profiles, Logging, i18n and AOP (ch. 7.3 to 7.6)

Pages = PDF (SBR p.N; printed = N−20). Version 2.7.18 [DATED].

## Profiles
- **[from source]** `@Profile` on `@Component`, `@Configuration` or `@ConfigurationProperties`; for beans registered via `@EnableConfigurationProperties`, the `@Profile` goes on the `@Configuration` that enables them (SBR p.133-134).
- **[from source]** Activate: `spring.profiles.active` (property, `--spring.profiles.active=...`, `-D` or `SPRING_PROFILES_ACTIVE`); default with no active profile = `default`, changeable via `spring.profiles.default` (SBR p.134, 566-567).
- **[from source]** `spring.profiles.active`, `spring.profiles.default` and `spring.profiles.include` **only apply in non-profile-specific documents** (not in `application-<profile>` nor in documents with `spring.config.activate.on-profile`) (SBR p.135-136). `scripts/sbr_propcheck.py` flags this (rule P01).
- **[from source]** More profiles without replacing the active ones: `spring.profiles.include`; groups: `spring.profiles.group.<name>[0]=...`; programmatic: `setAdditionalProfiles` (SBR p.135-137).
- **[from source]** The value of `spring.profiles.active` in the file is replaced by a system property/environment variable but **not** by `SpringApplicationBuilder.profiles()` (SBR p.567).

## Logging
- **[from source]** Commons Logging internally; Logback is the default with starters; default configurations exist for Java Util Logging, Log4j2 and Logback (SBR p.137). In a servlet container, JUL is not routed to the app's logs (SBR p.137).
- **[from source]** Default format: date/time, level, PID, `---`, thread, logger, message; Logback has no FATAL (it maps to ERROR) (SBR p.138).
- **[from source]** `--debug`/`debug=true` enables more detailed logging of core loggers (it does not log everything at DEBUG); `--trace`/`trace=true` is analogous (SBR p.138-139). ANSI colors: `spring.output.ansi.enabled` and `%clr` (SBR p.139).
- **[from source]** File: by default console only; set `logging.file.name` or `logging.file.path` (writes `spring.log` in the directory); rotation at **10 MB** (SBR p.140). Fine-grained rotation only with **Logback**: `logging.logback.rollingpolicy.{file-name-pattern, clean-history-on-start, max-file-size, total-size-cap, max-history (default 7)}`; other systems configure rotation in their own file (SBR p.140-141).
- **[from source]** Levels: `logging.level.<logger>=<level>` (TRACE, DEBUG, INFO, WARN, ERROR, FATAL, OFF) and `logging.level.root`; via environment variable it only works at package level, not class level (SBR p.141). Groups: `logging.group.<name>`; predefined `web` and `sql` (SBR p.141-142).
- **[from source]** `logging.register-shutdown-hook=false` turns off the hook (registered automatically except in war) (SBR p.142). `logging.config` and the system property `org.springframework.boot.logging.LoggingSystem` (value `none` turns off Boot's configuration); logging is initialized before the context, so `@PropertySource` does not control it (SBR p.143).
- **[from source]** Files per system: `logback-spring.xml|groovy`, `logback.xml|groovy`; `log4j2-spring.xml|log4j2.xml`; `logging.properties` (JUL; avoid in an executable jar). Prefer the `-spring` variants (SBR p.143).
- **[from source]** Properties passed on to system properties (`LOG_FILE`, `LOG_PATH`, `CONSOLE_LOG_PATTERN`, `FILE_LOG_PATTERN`, `LOG_LEVEL_PATTERN`, `PID` ...) (SBR p.143-144). In logging placeholders use `:` and not `:-` (SBR p.145). MDC via `logging.pattern.level` (SBR p.145).
- **[from source]** Logback extensions `<springProfile>` and `<springProperty>` only in `logback-spring.xml` (or via `logging.config`); they do not work with Logback's configuration scanning (SBR p.145-146).
- **[from source, how-to]** Includes `defaults.xml`, `console-appender.xml`, `file-appender.xml`; file-only logging requires a `logback-spring.xml` without the console appender + `logging.file.name` (SBR p.599-601). Log4j2: exclude `spring-boot-starter-logging` and include `spring-boot-starter-log4j2`; JUL routing with `java.util.logging.manager=org.apache.logging.log4j.jul.LogManager`; YAML/JSON and composite configuration (`logging.log4j2.config.override`) (SBR p.601-603). Note: "YAML/JSON" here is the **format of Log4j 2's configuration file** (`log4j2.yaml|yml|json|jsn`, with jackson-databind/dataformat-yaml; SBR p.602-603), **not** a JSON/ECS log output layout: the book does not cover structured log output (JSON/ECS/Logstash) -> NOT COVERED (see §Logging above for what the book covers: levels, groups, file, rotation, p.138-142).

## i18n and AOP
- **[from source]** Messages: looks for `messages` at the classpath root (a `messages.properties` must exist); `spring.messages.basename` (comma-separated list) and `spring.messages.fallback-to-system-locale` (SBR p.146-147).
- **[from source]** AOP: CGLIB by default; `spring.aop.proxy-target-class=false` uses JDK proxies; with AspectJ on the classpath, auto-proxying is enabled without `@EnableAspectJAutoProxy` (SBR p.147).

## Round 4 additions: logging in detail (Features 7.4 and how-to 17.7)
- **[from source]** Console output: by default ERROR, WARN and INFO messages are emitted; `--debug` (or `debug=true`) raises a set of core loggers (embedded container, Hibernate and Spring Boot) but does not put the whole application at DEBUG; `--trace` (or `trace=true`) turns on TRACE for the embedded container, Hibernate schema generation and the whole Spring portfolio (SBR p.138-139). Accepted log levels: ERROR, WARN, INFO, DEBUG, TRACE; the default format shows date/time with milliseconds, level, PID, the `---` separator, thread in brackets (it may be truncated on the console), logger name (usually abbreviated) and the message (SBR p.137-138).
- **[from source]** ANSI colors: the automatic detection can be overridden with `spring.output.ansi.enabled`; color is applied by the `%clr` conversion word, by default according to the level (FATAL and ERROR in red, WARN in yellow, INFO, DEBUG and TRACE in green), or chosen by option, such as `%clr(%d{yyyy-MM-dd HH:mm:ss.SSS}){yellow}`; supported colors and styles: blue, cyan, faint, green, magenta, red, yellow (SBR p.139-140).
- **[from source]** File table: without `logging.file.name` and without `logging.file.path` = console only; with `logging.file.name` = writes to the given file (exact path or relative to the current directory); with `logging.file.path` = writes `spring.log` in that directory. Files rotate when they reach 10 MB and, as on the console, ERROR, WARN and INFO are emitted by default. The `logging.*` properties are independent of the logging infrastructure: specific keys such as `logback.configurationFile` are not managed by Boot (SBR p.140).
- **[from source]** Rotation (Logback only; in Log4j2 configure it in `log4j2.xml` or `log4j2-spring.xml` itself): `logging.logback.rollingpolicy.file-name-pattern` (default `${LOG_FILE}.%d{yyyy-MM-dd}.%i.gz`, p.144), `clean-history-on-start`, `max-file-size`, `total-size-cap` and `max-history` (default 7) (SBR p.140-141, 144). These properties are also passed on as `LOGBACK_ROLLINGPOLICY_*` system properties (SBR p.144).
- **[from source]** Levels via environment variable: `LOGGING_LEVEL_ORG_SPRINGFRAMEWORK_WEB=DEBUG` adjusts `org.springframework.web`, but only works at package level, because relaxed binding converts variables to lowercase and cannot distinguish a class; for a class use `SPRING_APPLICATION_JSON` (SBR p.141). Group example: `logging.group.tomcat=org.apache.catalina,org.apache.coyote,org.apache.tomcat` and then `logging.level.tomcat=trace` (SBR p.141-142). Predefined groups: `web` = `org.springframework.core.codec`, `org.springframework.http`, `org.springframework.web`, `org.springframework.boot.actuate.endpoint.web` and `org.springframework.boot.web.servlet.ServletContextInitializerBeans`; `sql` = `org.springframework.jdbc.core`, `org.hibernate.SQL` and `org.jooq.tools.LoggerListener` (SBR p.142).
- **[from source]** Log shutdown hook: releases resources when the JVM ends and is registered automatically except in war; with complex context hierarchies it may not be enough (Logback offers context selectors) and then it is turned off with `logging.register-shutdown-hook=false` (SBR p.142). Choice of system: `logging.config` points to the configuration; the system property `org.springframework.boot.logging.LoggingSystem` accepts the class name of a `LoggingSystem` implementation, or `none` to turn off Boot's configuration; since logging is initialized before the `ApplicationContext`, `@PropertySource` does not control it (SBR p.143). Warnings: prefer the `-spring` variants (with `logback.xml` Spring cannot fully control initialization) and avoid `logging.properties` (JUL) in an executable jar due to known classloading problems (SBR p.143).
- **[from source]** Properties passed on to system properties (SBR p.143-144): `logging.exception-conversion-word` becomes `LOG_EXCEPTION_CONVERSION_WORD`, `logging.file.name` becomes `LOG_FILE`, `logging.file.path` becomes `LOG_PATH`, `logging.pattern.console` becomes `CONSOLE_LOG_PATTERN`, `logging.pattern.dateformat` becomes `LOG_DATEFORMAT_PATTERN`, `logging.charset.console` becomes `CONSOLE_LOG_CHARSET`, `logging.pattern.file` becomes `FILE_LOG_PATTERN`, `logging.charset.file` becomes `FILE_LOG_CHARSET` and `logging.pattern.level` becomes `LOG_LEVEL_PATTERN` (default `%5p`); `PID` is discovered when possible and if it is not already an OS variable. In log placeholders use Boot's syntax (`:` and not `:-` in Logback); for MDC override only the level pattern, e.g. `logging.pattern.level=user:%X{user} %5p` (SBR p.144-145).
- **[from source]** Logback extensions: `<springProfile>` accepts a profile name or expression (e.g. `production & (eu-central | eu-west)`, `dev | staging`, `!production`) and can appear anywhere in `<configuration>`; `<springProperty>` exposes `Environment` properties to Logback, with attributes `scope`, `name`, `source` and `defaultValue`; the `source` must be in kebab-case (SBR p.145-146). They do not work in `logback.xml` (loaded too early) nor with Logback's configuration scanning: changing the file produces errors such as "no applicable action for [springProperty]" or "[springProfile]" (SBR p.145).
- **[from source, how-to]** Logback: if you need nothing beyond levels, use `logging.level`; for fine tuning use the native file (`classpath:logback.xml` by default, location changeable via `logging.config`); with Spring extensions use `logback-spring.xml`. Boot provides under `org/springframework/boot/logging/logback/` the files `defaults.xml` (conversion rules, pattern properties and common logger settings), `console-appender.xml` (uses `CONSOLE_LOG_PATTERN`) and `file-appender.xml` (`RollingFileAppender` with `FILE_LOG_PATTERN` and `ROLLING_FILE_NAME_PATTERN`), plus the legacy `base.xml` (SBR p.599). Your file can use the system properties `${PID}`, `${LOG_FILE}`, `${LOG_PATH}`, `${LOG_EXCEPTION_CONVERSION_WORD}` and `${ROLLING_FILE_NAME_PATTERN}` (the latter comes from `logging.pattern.rolling-file-name`); ANSI colors on the console (not in a file) come from a dedicated converter, see `CONSOLE_LOG_PATTERN` in `defaults.xml` (SBR p.600). With Groovy on the classpath, `logback.groovy` also works and takes preference, but the Spring extensions are not supported in Groovy (a `logback-spring.groovy` is not detected) (SBR p.600).
- **[from source, how-to]** File-only logging: a `logback-spring.xml` that includes `defaults.xml` and `file-appender.xml` but not `console-appender.xml`, defines `LOG_FILE` and uses the `FILE` appender at the root, plus `logging.file.name` (e.g. `myapplication.log`) in `application.properties` (SBR p.600-601). Log4j 2: without the starters you need at least `spring-jcl`; with the starters, exclude `spring-boot-starter-logging` and include `spring-boot-starter-log4j2` (Maven) or use module replacement in Gradle (`replacedBy`); the Log4j starters gather common dependencies (e.g. Tomcat using `java.util.logging` with output configured by Log4j 2); to route `java.util.logging` to Log4j 2 set the system property `java.util.logging.manager` to `org.apache.logging.log4j.jul.LogManager` (SBR p.601-602). Alternative Log4j 2 configuration formats: YAML (`log4j2.yaml` or `log4j2.yml`, with `jackson-databind` and `jackson-dataformat-yaml`) and JSON (`log4j2.json` or `log4j2.jsn`, with `jackson-databind`); composite configuration via `logging.log4j2.config.override` with the locations of the secondary files, merged into the main one (SBR p.602-603).
