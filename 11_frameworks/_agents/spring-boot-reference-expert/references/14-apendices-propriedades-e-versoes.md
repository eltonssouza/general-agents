## Round 4 additions: Appendix B (metadata) and A.15-A.16 in detail
- **[from source]** Format: the metadata lives in `META-INF/spring-configuration-metadata.json`, with `groups` (contextual grouping, with no value of its own, e.g. `server` groups `server.port` and `server.address`), `properties` (item the user defines) and `hints` (help with values, e.g. `none`, `validate`, `update`, `create` and `create-drop` for `spring.jpa.hibernate.ddl-auto`) (SBR p.799-801). Not every property needs a group (SBR p.801). Most of it is generated at compile time from `@ConfigurationProperties`, and part of it can be written by hand for corner cases (SBR p.799).
- **[from source]** Attributes of `groups`: `name` (mandatory), `type`, `description`, `sourceType` and `sourceMethod` (SBR p.801-802). Attributes of `properties`: `name` (lowercase separated by dots; mandatory), `type` (full signature, including generics; primitives via the wrapper, e.g. `java.lang.Boolean`), `description` (short paragraph, first line a concise summary, last line ending with a period), `sourceType`, `defaultValue` (can be an array) and `deprecation` (SBR p.802-803).
- **[from source]** `deprecation` (SBR p.803-804): `level` can be `warning` (default; the property should still be bound in the environment) or `error` (the property is no longer managed and is **not bound**); `reason` and `replacement` (full name of the replacement property). Before Spring Boot 1.3 there was a boolean attribute `deprecated`, still accepted but discouraged. In code, `@DeprecatedConfigurationProperty(replacement = "my.app.name")` on the getter (the example renames `my.app.target` to `my.app.name`); there is no way to set `level` by annotation (`warning` is assumed); when the old methods leave the public API the automatic hint disappears, and to keep the warning add manual metadata with level `error` (SBR p.803-804); this manual metadata goes in `META-INF/additional-spring-configuration-metadata.json`, which the processor merges into the main one (SBR p.820; see below).
- **[from source]** Manual hints (SBR p.804-808): `hints` have `name`, `values` (each with a mandatory `value` and `description`) and `providers` (name and parameters). For a `Map` property, hints are given for keys and values, but not for the map itself, with the suffixes `.keys` and `.values` (e.g. `my.contexts.keys` with `sample1` and `sample2`); the book recommends an `Enum` instead, as the most effective form of autocompletion (SBR p.805-807). Official providers: `any` (accepts extra values), `class-reference` (parameters `target`, default none, and `concrete`, default true; SBR p.809), `handle-as` (parameter `target` with default none, declared mandatory; SBR p.809: `Enum`, `Charset`, `Locale`, `MimeType` or `Resource`), `logger-name` (parameter `group`, default true) , `spring-bean-reference` (parameter `target`, default none; the table does not declare it mandatory, unlike `handle-as`; SBR p.812) and `spring-profile-name`; only one provider is active per property, put the most powerful first, and IDEs may implement some, all or none of them (SBR p.807-813). The binder does not know the metadata: with `spring-bean-reference` you still need to turn the bean name into a reference through the `ApplicationContext` (SBR p.812).
- **[from source]** Annotation processor (SBR p.813-820): `spring-boot-configuration-processor` (Maven `optional`; Gradle in `annotationProcessor`); with an `additional-spring-configuration-metadata.json`, the `compileJava` task must depend on `processResources` (SBR p.813). With AspectJ make sure the processor runs only once (for example an explicit `maven-apt-plugin`, or `<proc>none</proc>` in the `maven-compiler-plugin`); with Lombok its processor must run **before** (order in `annotationProcessors` in Maven; without that attribute, declare `lombok` before the `spring-boot-configuration-processor`) (SBR p.814). The processor picks up classes and methods with `@ConfigurationProperties`; with `@ConstructorBinding` it expects a constructor and creates one property per parameter; otherwise it uses getters and setters (collections and maps are detected even with only a getter) and supports Lombok's `@Data`, `@Value`, `@Getter` and `@Setter` (SBR p.814). The description comes from the field's Javadoc, plain text only (SBR p.816). Defaults must be static (do not reference a constant from another class) and the processor **does not detect defaults of Enums or of collections**: use manual metadata (e.g. `my.messaging.addresses` with `["a","b"]` and `my.messaging.container-type` with `simple`); only the `name` is mandatory to complement an existing property (SBR p.816-818). Inner classes become nested properties (e.g. `my.server.host.ip`); `@NestedConfigurationProperty` treats an ordinary (non-inner) class as nested and does not affect collections and maps (SBR p.818-820). The processor merges `META-INF/additional-spring-configuration-metadata.json` into the main one: for an already detected property, description, default and deprecation are overridden if provided; if it is not detected in the module, it is added as new; the format is the same as the main file and the file is optional (SBR p.820).
- **[from source]** Appendix A.15-A.16 (SBR p.797-799): `spring.devtools.restart.trigger-file` is the simple name (without a path) of a classpath file whose change triggers the restart check; if absent, any classpath change triggers it; `spring.test.database.replace` (default `any`) is the type of existing DataSource to replace; `spring.test.mockmvc.print` (default `default`) is the MVC print option.
